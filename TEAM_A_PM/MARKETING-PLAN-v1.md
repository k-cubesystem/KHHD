## 1. Track A — 유입분석 시스템 (계측 기반 공사)

### 1.0 감사 결론

GA4는 로드되고 클라이언트 이벤트 28종 중 19종이 발화 중이다. 그러나 **광고 운영의 4대 전제가 전부 비어 있다**:
유입 귀속(UTM) 전무 · purchase가 매출을 기록하지 않음 · OAuth 가입 미계측 · 서버측 전환 전송 부재.
이 상태로 집행하면 "돈은 나가는데 무엇이 벌어 왔는지 모르는" 구조가 되고, **소급 복구가 불가능한 것은 UTM뿐**이다.

### 1.1 P0 — 광고 집행 전 필수 (이것 없이 Track B 금지)

**A-1. UTM 캡처 → 가입 귀속 파이프라인** _(소급 불가 — 최우선)_

- `middleware.ts`(이미 전 경로 매처)에서 `utm_*`·`gclid`·`fbclid` 감지 → first-touch를 쿠키(90일)에 보존
- `utm_tracking` 테이블·`get_utm_performance` RPC는 **이미 존재**(20260213 마이그레이션) — INSERT 쓰기만 채우면 됨
- `profiles`에 귀속 컬럼 추가(`first_utm jsonb`, `signup_referrer text`) + 가입 완료 시점(이메일 폼 + **OAuth 콜백 라우트 둘 다**)에 쿠키 → DB 확정
- 공유·초대 링크에 UTM 자동 부착(`kakao-share-button`·`referral.ts`) — 바이럴이 direct로 뭉개지는 것 방지

**A-2. GA4 전자상거래 정상화** _(ROAS 산출의 전제)_

- `trackEvent`에 `currency: 'KRW'`·`transaction_id`·`items[]` 지원 추가
- 실원화 결제(복채 충전)를 표준 `purchase`로 승격 — 현재는 커스텀 `bokchae_charge`라 GA4 매출 리포트에 안 잡힘
- 구독 성공 페이지의 `value: 0` 하드코딩 제거 → 서버 확정 금액 사용 (URL 쿼리 아닌 서버값 — 조작 방지 겸)
- 앱내 재화(복채) 소비는 `purchase`에서 **분리** — `spend_virtual_currency` 표준 이벤트로. 광고 플랫폼에 가짜 매출 학습 금지
- 4단계 결제 퍼널의 끊긴 고리 `storeTab` 발화 추가

**A-3. OAuth 가입 계측** _(가입 전환 과반 유실 추정 — 카카오 비중 고려)_

- `auth/callback` 라우트에서 신규 가입 판정 → 서버측 전송(A-4의 MP 경유) 또는 첫 랜딩 클라이언트 브릿지로 `sign_up` 발화
- method 파라미터(email/google/kakao)로 가입 채널 분해

**A-4. 서버측 전환 전송 (GA4 Measurement Protocol)**

- Toss `PAYMENT.DONE` 웹훅 → MP `purchase` 전송 (결제 확정의 유일한 신뢰 소스에서 쏨 — 광고차단·이탈·ITP 무관)
- `client_id`는 결제 시작 시점에 gtag에서 회수해 orderId에 동반 저장
- 부수 수복: 서버 액션에서 호출돼 **영구 무발화**인 `trackEvent` 4곳(신당 과금 이벤트 전부)을 MP 경로로 전환
- env: `GA4_API_SECRET` 신설(.env.example 갱신 — `NEXT_PUBLIC_GA_ID`도 현재 누락돼 있음)

**A-5. 도메인·랜딩 정합** _(광고 CTR 직결)_

- `NEXT_PUBLIC_SITE_URL=https://k-haehwadang.com` 확정 → `metadataBase`(현재 VERCEL_URL — OG가 배포 해시 도메인을 가리킬 수 있음)·sitemap·robots 일원화
- sitemap: `/story` 추가(유일한 마케팅 상세 랜딩이 누락) · 로그인 필수 `/protected/*` 5개 제거
- 루트 `opengraph-image.png`/`.tsx` 동시 존재 충돌 정리
- Google Search Console·네이버 서치어드바이저 verification 메타 추가

### 1.2 P1 — 집행 직후 필요

- **A-6. 캠페인 소재 계측**: 이벤트 배너·팝업에 노출/클릭 이벤트(현재 0건 — 소재 A/B 판단 근거 없음)
- **A-7. 광고 픽셀**: 채널 확정 후 Meta 픽셀(+CAPI는 후순위)·카카오 픽셀·네이버 전환추적. **CSP 수정 선행**(next.config.ts 화이트리스트에 해당 도메인 없음)
- **A-8. 어드민 유입 대시보드**: `getUTMPerformance`·`getFunnelAnalysis`·`getRetentionCohort`·`getConversionMetrics` — **함수 4개가 이미 구현돼 있으나 어떤 UI에서도 미사용**. 화면만 붙이면 됨 (A-1이 선행돼야 데이터가 참)

### 1.3 P2 — 확장

- 서버 이벤트 스키마 일반화(웹훅 외 주요 액션), BigQuery 내보내기(월 데이터 쌓인 뒤), A/B 실험 프레임(후순위 — 트래픽 규모 확보 전 무의미)

### 1.4 명시적 비목표

- 자체 분석 DB/CDP 구축 안 함(GA4+utm_tracking으로 충분한 규모), 동의관리플랫폼(CMP) 도입은 별도 법무 검토 후, 앱스토어 어트리뷰션(MMP)은 네이티브 앱 출시 전 불필요

## 3. Track C — 콘텐츠 마케팅 (자산 활용 기획)

### 3.1 원칙

1. **앱이 곧 스튜디오다** — 신당 화면·의례 연출·신위·테마가 전부 촬영 세트. 별도 소재 제작비의 대부분을 제거
2. **사실만 말한다** — 효험이 아니라 **체험과 세계관**을 판다(가드레일과 콘텐츠 전략의 일치)
3. **하나의 원본 → 3플랫폼 배포** — 9:16 원본을 릴스/쇼츠/틱톡에 동시 배포(세이프에어리어가 3사 최보수 값이라 가능)

### 3.2 콘텐츠 필라 5개

**필라 1 — 「오늘의 운세」 데일리 쇼츠** _(양산형 · 주 5~7회)_

- 형식: 玄 배경 + 금박 이미지(nano-banana) + 오늘 날짜 간지·절기 + 운세 한 줄 + 앰비언스 BGM
- 제작: 템플릿화하면 편당 10분 내 — `kie.mjs`(이미지) → `post.mjs caption`(자막) → `audio`(shrine-ambience 루프)
- CTA: "내 사주로 보는 오늘은? — 오늘의 운세 무료" (실값 기반 무료 훅)
- 목적: 도달·습관성 구독. 계정의 «맥박»

**필라 2 — 신당 세계관 시네마틱** _(주 1~2회 · 품질형)_

- 형식: 테마 16종 방 파노라마 + 신위·신수 연출 + 의례 장면(오방기 문복, 척전, 액막이 부적 태우기)을 화면 녹화·후처리
- 스토리 축: "척전 — 태종이 한양 천도를 결정한 그 점법"(실록 전거 = 사실 스토리텔링), "오방기 문복 절차 — 고축부터 송신까지", 테마별 세계관(용궁·대장간·연등…)
