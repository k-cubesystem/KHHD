# 토스 결제경로 심사 제출 — 요구사항 대조표

작성 2026-08-17 · 근거: 토스페이먼츠 「홈페이지 결제경로 제작 가이드」 **일반결제용(17p)·정기결제용(14p)**

---

## 0. 먼저 — 이건 코드 연동 문서가 아니다

두 PDF 는 **카드사 심사용 「결제경로 파일」을 만드는 방법**을 알려주는 문서다(가이드 2p).
결제가 이루어지는 과정을 **화면 캡처로 시각화**해서 제출하는 것이고, API 명세는 한 줄도 없다.

> "결제경로 제작은 기본적으로 «화면 캡처» 를 통해 제작되어야 해요.
> 본 가이드에 따라 **누락되는 정보 없이** 제작되어야 카드사 심사가 정상적으로 이루어질 수 있어요."

즉 우리가 할 일은 두 갈래다 — **①캡처할 화면이 실제로 존재하게 만들기(코드)**,
**②순서대로 캡처해서 파일 만들기(운영)**.

두 가이드는 페이지 3·5·6·8~14 가 **완전히 동일**하다. 다른 건 카드 결제경로(⑥) 뿐이다.

## 1. 6단계 요구사항 vs 우리 현황

| #   | 요구사항                                                                                      | 우리 현황                                                                                                                                        | 판정                                       |
| --- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------ |
| ①   | **표지에 가맹점 정보** — 상호명 / 사업자번호 / URL / **테스트계정**                           | URL·상호·사업자번호 있음. **테스트계정은 CEO 지정 필요**                                                                                         | ⚠️ 준비물                                  |
| ②   | **하단정보 캡처** — 상호명·대표자명·사업자등록번호·통신판매업신고번호·사업장주소·유선전화번호 | 푸터에 **6항목 전부** 있음 (큐브시스템 · 박대건 · 205-16-69546 · 제2024-의정부흥선-0264호 · 경기도 의정부시 신촌로 39번길 50-20 · 010-2311-2010) | ✅                                         |
| ③   | **환불규정 캡처**(무형상품)                                                                   | `/terms` **제7조 (청약철회 및 환불)** 로그인 없이 열림                                                                                           | ✅                                         |
| ④   | **로그인 / 회원가입 경로 캡처**                                                               | `/auth/login`, `/auth/sign-up`                                                                                                                   | ✅                                         |
| ⑤   | **상품선택 / 구매과정 캡처**                                                                  | `/protected/store` 4탭. `orderName`·`amount(KRW)` 정상                                                                                           | ✅ (로그인 필요 — ①의 테스트계정으로 캡처) |
| ⑥   | **카드 결제경로 캡처**                                                                        | **결제창이 실제로 떠야 캡처 가능 → §2 선결**                                                                                                     | 🔴 막힘                                    |

⚠️ ②의 「유선전화번호」는 가이드 **예시 자체가 `010-0000-0000`** 이다(7p). 휴대전화 번호로 반려되지 않는다.
🔴 다만 **토스페이먼츠에 등록된 사업자등록증과 항목이 모두 같아야** 한다 — 대조는 CEO 확인.

### ⑥ 카드 결제경로 — 두 가지를 다 캡처해야 한다

- **일반결제(`khaehwjxqe`)**: 카드 선택 → 카드사 인증까지.
  🔴 **비씨(BC)카드는 실제 결제 화면(페이북 ISP 창)까지** 캡처해야 한다(일반결제 가이드 16p).
- **정기결제(`bill_khaehqj1a`)**: **정기결제용 카드 입력창**(빌링키 등록창)까지 캡처
  — 「카드 정보를 입력해주세요」 + 「본인 정보를 입력해주세요」 두 창 (정기결제 15p / 일반결제 17p).

## 2. 🔴 캡처 전에 고쳐야 할 코드 2건

⑥을 캡처하려면 **결제창이 실제로 떠야 한다.** 지금 상태로는 안 뜨거나, 둘 중 한쪽이 거절된다.

### 2-1. 상점아이디가 둘인데 코드는 키 한 쌍만 상정한다

토스는 MID 마다 키쌍(클라이언트/시크릿)을 따로 준다. 지금은 시크릿 하나가 전부를 쓴다.

| 경로                                                                           | 엔드포인트                         | 필요한 MID            |
| ------------------------------------------------------------------------------ | ---------------------------------- | --------------------- |
| `app/actions/payment/payment.ts:70`                                            | `/v1/payments/confirm`             | 일반 `khaehwjxqe`     |
| `app/actions/payment/subscription.ts:317`                                      | `/v1/billing/authorizations/issue` | 빌링 `bill_khaehqj1a` |
| `app/actions/payment/subscription.ts:423` · `app/api/cron/billing/route.ts:52` | `/v1/billing/{billingKey}`         | 빌링                  |
| `app/actions/payment/cancel-request.ts:391,668`                                | `/v1/payments/{key}/cancel`        | **결제가 일어난 쪽**  |
| `app/api/webhooks/toss/route.ts`                                               | 웹훅 Basic 인증                    | MID 별로 다름         |

- 클라이언트도 같다. `lib/services/tosspayments.ts` 의 SDK 하나를
  `requestBillingAuth`(빌링) **5곳**과 `requestPayment`/`widgets`(일반) **2곳**이 같이 쓴다.
- ✅ `lib/domain/payment/toss-cancel.ts` 는 `secretKey` 를 **인자로 받는다** — 호출자만 고치면 된다.
- 🔴 웹훅은 **양쪽 시크릿을 다 통과**시켜야 한다. 지금은 한쪽이 전량 거절된다.

### 2-2. 클라이언트 키 환경변수 이름이 셋으로 갈렸다

| 위치                                                        | 이름                                   |
| ----------------------------------------------------------- | -------------------------------------- |
| `lib/config/env.ts:14` (검증)                               | `NEXT_PUBLIC_TOSS_CLIENT_KEY`          |
| `lib/services/tosspayments.ts:3` (**실제로 읽음**)          | `NEXT_PUBLIC_TOSS_PAYMENTS_CLIENT_KEY` |
| `app/protected/membership/checkout/page.tsx:75` (오류 문구) | `TOSS_CLIENT_KEY`                      |

**스키마대로 심으면 결제 모듈이 조용히 초기화 실패한다.** 그리고 오류 문구는 엉뚱한 변수를 가리켜
원인 찾는 데 시간을 버리게 된다. 이름을 하나로 통일하고, env 스키마가 «실제로 읽는 변수» 를 검증하게 바꾼다.

⚠️ 클라이언트 키는 모듈 최상단에서 읽혀 **빌드에 인라인**된다 — 키를 바꾸면 **재배포**해야 반영된다.
⚠️ `tosspayments.ts:10` 이 `console.error` 단독 — 결제 초기화 실패가 Sentry 에 안 올라간다(logger 로 교체).

## 3. 환경변수 이름 — 확정 (이대로 심으면 된다)

키를 받는 사람과 코드를 고치는 사람이 다르므로 **이름을 먼저 못 박는다.** §2-2 의 세 갈래
이름은 아래로 통일하고, env 스키마가 **실제로 읽는 변수**를 검증하도록 바꾼다.

| 용도                           | 환경변수 이름                         | 값의 생김새   | 공개 여부           |
| ------------------------------ | ------------------------------------- | ------------- | ------------------- |
| 일반결제 `khaehwjxqe` 클라     | `NEXT_PUBLIC_TOSS_CLIENT_KEY`         | `live_ck_...` | 브라우저 노출(정상) |
| 일반결제 `khaehwjxqe` 서버     | `TOSS_SECRET_KEY`                     | `live_sk_...` | **서버 전용**       |
| 정기결제 `bill_khaehqj1a` 클라 | `NEXT_PUBLIC_TOSS_BILLING_CLIENT_KEY` | `live_ck_...` | 브라우저 노출(정상) |
| 정기결제 `bill_khaehqj1a` 서버 | `TOSS_BILLING_SECRET_KEY`             | `live_sk_...` | **서버 전용**       |

🔴 `NEXT_PUBLIC_` 접두사가 붙은 둘은 **브라우저에 그대로 실린다** — 원래 그런 키다(공개용).
시크릿 키 둘에는 절대 `NEXT_PUBLIC_` 을 붙이지 않는다. 붙는 순간 시크릿이 공개된다.

### 지금 Vercel(`hhd`, Production)에 심겨 있는 것 — 실측 2026-08-17

| 이름                                   | 코드가 읽나                            | 처리                                    |
| -------------------------------------- | -------------------------------------- | --------------------------------------- |
| `TOSS_PAYMENTS_SECRET_KEY`             | ✅ 승인·빌링·취소·웹훅 **전부**        | → `TOSS_SECRET_KEY` 로 이름 변경        |
| `NEXT_PUBLIC_TOSS_PAYMENTS_CLIENT_KEY` | ✅ SDK 가 읽음                         | → `NEXT_PUBLIC_TOSS_CLIENT_KEY` 로 통합 |
| `NEXT_PUBLIC_TOSS_CLIENT_KEY`          | ❌ 스키마만 검증, 읽는 코드 없음       | **이 이름을 정본으로 승격**             |
| `TOSS_WEBHOOK_SECRET`                  | ❌ **아무도 안 읽는 고아**(163일 방치) | 삭제 — 웹훅은 시크릿 키로 인증한다      |

🔴 고아 변수 둘(`NEXT_PUBLIC_TOSS_CLIENT_KEY` 의 옛 용법 · `TOSS_WEBHOOK_SECRET`)이 «설정했으니
됐겠지» 라는 착각을 만든다. 실연동에서 값을 엉뚱한 칸에 넣고 안 된다고 헤매기 딱 좋은 자리다.

## 4. 진행 순서

1. **CEO** — 토스 개발자센터에서 **두 상점의 키 4개** 확보(§3 표)
2. **CEO** — Vercel 프로젝트 `hhd` 환경변수에 4개 투입 (Production)
3. **CEO** — 토스 콘솔에 **웹훅 등록**: `https://k-haehwadang.com/api/webhooks/toss`
   — **두 상점 모두** 같은 주소로. 이벤트는 `PAYMENT_STATUS_CHANGED` 포함
4. **CEO** — 심사용 **테스트계정** 지정(카드사 심사자가 로그인해서 ⑤·⑥을 본다)
5. **코드** — §2-1 키 두 쌍 분리 · §2-2 이름 통일 · `console.error` → logger
6. **배포** — 클라이언트 키는 빌드에 인라인되므로 **환경변수 투입 후 재배포**해야 반영된다
7. **캡처** — ①~⑥ 순서대로. ⑥은 일반·정기 **둘 다**, BC카드는 페이북 창까지
8. **제출** — 누락 항목이 있으면 심사가 진행되지 않는다

## 4. 캡처할 때 주의

- 브라우저 **주소창이 보이게** 캡처한다(가이드 예시 전부 주소창 포함).
- 하단정보·환불규정은 **로그인 없이** 보이는 화면으로 캡처 — 우리는 둘 다 공개라 문제없다.
- 상품 화면에 **상품명과 금액**이 함께 보여야 한다(`orderName` 이 「팩 이름 (복채 N만냥)」 형태라 충족).
- 정기결제는 「결제 정보 변경」 화면까지 있는 예시다 — 우리 구독 관리 화면도 함께 찍어두면 안전하다.
