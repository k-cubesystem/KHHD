### P2 — 백로그 상단 (터지는 조건이 명확한 실결함)

**P2-1. 오방기 뽑기 응답에 `.catch` 없음 → 네트워크 실패 시 "기를 펴는 중…" 영구 고착**

- `ObangkiSheet.tsx:151-169` — `void drawObangki(...).then(...)`만 있다. 액션 reject(오프라인·배포 순단) 시 outcome이 영영 null → 재시도·오류 문구 없이 정지(출구는 헤더 뒤로가기뿐). 수정: `.catch(() => setOutcome({ success:false, error:'DRAW_FAILED' }))`.

**P2-2. 백일기도 시작/갈무리에 try/catch 없음 → 실패 시 버튼 영구 스피너**

- `baekil-client.tsx:40-70` — `setBusy(true); await 액션` 이 reject하면 `setBusy(false)` 미도달 → locked 고착. 수정: try/finally.

**P2-3. 백일기도 성공 토스트 직후 전체 리로드 → 보상 안내가 지워진다**

- `baekil-client.tsx:38,54,69` — `toast.success('목패을 받았습니다 · 소원끈 1개…')` 직후 `window.location.reload()`. sonner 토스트는 리로드를 못 넘기므로 **완주 보상 피드백이 사실상 표시 0초**. 수정: `router.refresh()`로 전환(토스트 생존 + 전체 리로드 비용 제거).

**P2-4. 유료 오방기 환불 실패가 무기록으로 사라진다**

- `lib/services/bokchae.ts:49-54` `refundBokchae`가 RPC/insert 결과를 안 본다 + 호출부(`rituals.ts:326`)도 미확인. "차감 성공 → 기록 실패 → 환불도 실패" 겹침 시 복채 증발이 로그 한 줄 없이 지나간다. 수정: 환불 실패 시 `logger.error`+Sentry 캡처(유일한 사후 복구 단서).

**P2-5. `shrine-30-inspect` 스펙 진부 2건 — 현재 항상 실패**

## ④ 총평 — 디버깅이 필요한 곳

**1) 오늘의 두 P0는 같은 뿌리다: "화면이 죽는 결함은 이 프로젝트의 어떤 게이트도 재지 않는다."**
styled-jsx 무증상 사망(7/30 발견)을 겪고 `check-animation-css.mjs` 게이트까지 만들었지만, 그 게이트는
**"CSS가 어느 청크에든 존재하는가"**를 잰다. P0-1은 CSS가 존재하되 **그 라우트에 연결 안 된** 경우라 통과했고,
P0-2는 CSS·DOM 모두 정상인데 **z-계층이 겹치는** 경우라 애초에 측정 대상이 아니다. `feedback_gate_measures_wrong_thing`
메모의 재림이다. 처방 두 가지 — ① 게이트를 라우트 단위로: 빌드 매니페스트에서 의식 라우트가 shrine-scene 청크를
참조하는지 대조(이번 감사가 쓴 방법 그대로 스크립트화 가능). ② 의식 3종의 **국면 완주 e2e** 1본(무료분만 쓰는
지금의 감사 보조 스펙이 원형) — 오늘 문제 전부가 이 한 본이면 배포 전에 잡혔다.

**2) e2e 스모크는 "돌리면 잡는" 상태가 아니라 "돌려도 죽어 있는" 상태다.**
6테스트 중 2개는 제품이 아니라 스펙이 낡아 실패하고(P2-5·6, 각각 7/25·안2.3부터), 1개는 계정 전제 미충족으로
스킵된다. 오늘 셀렉터 3건을 고치면서도 같은 파일 7줄 아래의 진부 단언은 남았다 — **스펙 수정 후 1회 실행**이
규율이 되어야 한다(이번이 UI 재편 후 첫 실행이었다). 테스트 계정에 가족 1명 등록 + banga 보유 부여(무료 지급
경로로)를 해 두면 family-shrine 스킵과 팻말·사랑방 커버리지 공백이 함께 풀린다.

**3) 새 의식 UI의 공통 약점은 "실패 경로의 부재"다.**
성공 경로는 낙관 UI·멱등 RPC·환불까지 잘 설계됐는데, **액션 promise가 reject하는 경우**(오프라인·배포 순단)를
세 화면 모두 안 받는다(P2-1·2). 무료 의식은 새로고침으로 풀리지만 오방기는 유료 재화가 걸린 화면이라
고착 상태가 곧 CS 티켓이다. `.then` 뒤에 `.catch` 한 줄씩, 오늘 붙이는 것을 권한다.

**4) 서버 쪽은 견고하다.** 의식 3종의 도메인 순수함수·RPC 원자성·과금 순서(무료 먼저→명시 동의→차감→실패 시
환불)·보상 멱등·RLS 쓰기 차단은 전 구간 잘 짜였고 1,275개 유닛테스트가 실제로 그 층을 덮고 있다. 남은 서버측
개선은 P2-4(환불 실패 가시화) 하나다. **오늘 터질 것은 전부 클라이언트 층에 있다.**

수정 우선순위 제안: P0-1(1줄) → P0-2(1곳) → P1-1 → P2-1~3(각 1~3줄) → 스펙 2본 갱신 후 e2e 재실행으로 마감.
