## 0. 한 줄

직장·재물은 **이 라인업에서 유일하게 «진짜 엔진이 이미 다 만들어져 있는» 주제**다.
관상은 사진을 다시 읽어야 하고 풍수는 결정론 모듈을 새로 써야 하지만, 직장·재물은
`trend_career` 와 `WEALTH_DEEP` 이 **이미 라이브에 있고, 아무도 링크하지 않는 채로 놀고 있다.**

그래서 이 문서의 과업은 만드는 것이 아니라 **접수(接收)**다.
새로 쓰는 코드는 테마당 30줄짜리 판정 함수 8개뿐이고, 나머지는 전부 배선이다.

### 1-2. 🔴 새로 찾은 것 ① — 재물 심층은 «본인»에게 동작하지 않는다

`app/protected/analysis/wealth/wealth-analysis-content.tsx:60`

```ts
if (targetId) {
  const { data } = await supabase.from('family_members').select(...).eq('id', targetId).single()
```

`analyzeWealth` 도 서버에서 `family_members` 를 다시 조회한다(`wealth.ts:82`).
그런데 이 앱의 대상 식별자는 **`v_destiny_targets`** 다 —
`profiles`(본인) **UNION ALL** `family_members`(가족) 이고, 본인의 id 는 `profiles.id` 다
(`20260722_leap_month_column.sql`).

→ **본인 대상으로는 `family_members` 조회가 비어 5만냥짜리 기능이 「대상 정보를 찾을 수 없습니다」로
끝난다.** (환불 배선은 살아 있어 복채는 돌아온다.) 게다가 살아 있는 링크 3곳은 전부
`?targetId=` **없는 맨 경로**라, 들어가도 `member` 가 null 이라 분석 버튼이 아무 일도 하지 않는다.

> 🔴 **테마 층은 `analyzeWealth` 를 그대로 호출하면 안 된다.** 호출 전에 대상 해석을
> `getDestinyTarget`(= `v_destiny_targets`)로 통일해야 한다. 마스터 §11 T-0의 실제 작업량은
> 「리다이렉트 걸기」가 아니라 **여기까지**다.

### 1-3. 🔴 새로 찾은 것 ② — 「투자 적기」는 **화면에 없다**. 프롬프트와 저장본에만 있다

**저장까지 하고 있는데, 아무도 보지 않는다.**

→ **처방: 출력 스키마에서 삭제.** 화면이 깨지지 않는다(렌더하는 곳이 없다). 삭제하면

조사일 2026-08-12. 🔴 **설문(방법론·표본 확인)과 정황(언론 인용만)과 추측(데이터 부재)을 구분해

> 않는다.** 앱 화면에는 애초에 통계를 싣지 않는다(§2-6).

## 3. 규율 — 이 세트가 지켜야 하는 선 (테마별 항목보다 먼저 읽을 것)

마스터 §9를 직장·재물에 맞게 **집행 가능한 형태**로 옮긴 것이다. 세 개의 벽이 있다.

### 3-1. 🔴 벽 ① 채용절차법 — 사장-직원 주제를 살리는 유일한 길

오늘(2026-08-12) `/business` 의 「채용·승진 적합도」를 이 사유로 **삭제했다.** 삭제만 한 게 아니라
회귀 테스트로 못 박았다 — `app/business/__tests__/copy.test.ts`:

```ts
it('채용·승진 판단 도구로 팔지 않는다', () => {
  for (const line of ALL_COPY) {
    expect(line).not.toContain('채용 적합도')
    expect(line).not.toContain('승진')
  }
})
```

**근거**: 채용절차법 §4의3(직무 무관 정보 요구·수집 금지, 과태료 500만원 이하) ·
고용정책기본법 §7①(모집·채용 시 차별 금지). 생년월일시는 직무 수행과 무관한 정보다.

**세 갈래 판정**(마스터 §9-2 그대로 승계)

| 갈래                                                  | 판정        | 본 세트에서                               |
| ----------------------------------------------------- | ----------- | ----------------------------------------- |
| ① 지원자를 놓고 뽑을지 말지 (「내 직원 사주 고르자」) | 🔴 **금지** | **테마 0종.** 설계에 자리를 만들지 않는다 |
| ② **이미 함께 일하는** 사람과의 소통·관계 이해        | ✅ 허용     | **C-4** (PAIR, WORK 관계군)               |
| ③ **본인 사주만** 보는 「사람 인연의 결」             | ✅ 허용     | **C-3** (SOLO, 상대 정보 0)               |

> CEO 예시 「직원복이 없는 건지… 보는 눈이 없는 건지」는 **③으로 그대로 살아난다.**
> 이건 사장 본인 사주의 문제이지 누구를 심사하는 게 아니다. 원래 톤에 가장 충실한 형태다.

**②(C-4)에 코드로 강제할 것 — 문구가 아니라 기능 제약이다**

1. 🔴 **지원자 정보 입력 UI를 만들지 않는다.** 대상은 **이미 등록된 인연**에서만 고를 수 있다.
   테마 상세에서 「새 사람 추가」로 바로 들어가는 경로를 두지 않는다 — 그 경로가 곧 면접자 입력 폼이 된다.
2. 인연 등록 시 체크: 「**이미 함께 일하고 있는 분**의 정보만 입력해주세요. 채용 절차 중인
   지원자의 정보는 입력하실 수 없습니다.」 (체크 없이 저장 불가)
3. **결과에 등급·서열·합불이 없다** — A/B/C, 적합·부적합, 총점 숫자 전부 금지.
   밴드(낮음/보통/높음)와 막대 길이만(마스터 §4-2·§12-2).
4. 상단 강화 고지 고정: 「이 풀이는 이미 함께 일하고 있는 사람과의 소통을 돕기 위한 것입니다.
   채용·평가·인사 결정의 근거로 사용할 수 없습니다.」
5. 카피·결과·프롬프트 전역 금지어: `채용 뽑 면접 지원자 적합도 합격 선발 승진 자를 해고 권고사직`

🔴 **라이브 문구 정정 1건**(마스터 T-5와 동일 건): `focus-groups.ts` `WORK.label` =
「직장 (**같이 일해도 되는 사람인가**)」 — 「~해도 되는 사람인가」는 **선별 판단**으로 읽힌다.
같은 파일 `WORK.questions[0]` 「시너지가 나나요, **소모가 되나요**?」도 상대 평가형이다.

| 현행                                                    | 권고                                      |
| ------------------------------------------------------- | ----------------------------------------- |
| `WORK.label` 「직장 (같이 일해도 되는 사람인가)」       | 「직장 (**어떻게 맞춰 일할까**)」         |
| `WORK.questions[0]` 「시너지가 나나요, 소모가 되나요?」 | 「**어디서 부딪히고 어디서 잘 맞나요?**」 |

`BUSINESS` 군은 **근로계약이 아닌 동업·거래**라 채용절차법 밖이다 — 현행 유지(W-3이 그대로 쓴다).

### 3-2. 🔴 벽 ② 자본시장법 — 재물 테마가 「사라/팔아라」로 읽히면 끝이다

대가를 받고 투자 판단을 조언하면 유사투자자문 영역과 닿는다. 풍수 문서도 §감정평가·투자자문
경계를 법무 확인 항목으로 올렸다. 재물 테마는 **자기이해 축으로만** 설계한다.

**출력 스키마에 자리를 만들지 않는다** — 이것이 문구 규율보다 강한 방어다(마스터 §9-4).

| 만들지 않는 필드                       | 대신 있는 것                                    |
| -------------------------------------- | ----------------------------------------------- |
| 종목·상품·자산군 이름                  | 없음. 어휘 자체를 금지어로 차단                 |
| 매수·매도 시점(`bestMonth`·`bestWeek`) | **W-2는 `timings: []` — 시기 배열 자체가 빈다** |
| 수익률·확률·목표가                     | 없음                                            |
| 「투자 적기」 라벨                     | 「**지출이 몰리는 달**」(방어적 서술)로만       |

🔴 W-1(돈이 안 모임)은 `keyCautionMonths` 를 쓰되 **「돈이 나가는 달」로만** 쓴다.
「이 달에 넣으세요」는 없고 「이 달은 지출이 몰리니 미루세요」만 있다.
**비대칭이 의도다** — 지출 경계는 소비자 보호 방향이고, 매수 시점은 투자 권유 방향이다.

강화 고지(마스터 §9-4 표 3행 그대로): 「이 풀이는 투자 자문이 아닙니다. 특정 상품·종목·매매
시점을 권유하지 않으며, 투자 판단과 책임은 본인에게 있습니다.」

### 3-3. 벽 ③ 표시광고법 — CEO 톤을 살리면서 효과 단정만 버린다

CEO가 준 두 문장이 이 세트의 톤 기준선이다. **그대로는 못 쓴다. 결을 남기고 단정을 버린다.**

| CEO 원문                                                        | 문제                                                       | 변환                                                                       | 어디로 갔나           |
| --------------------------------------------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------- | --------------------- |
| 「직원복이 없는 건지… 보는 눈이 없는 건지」                     | **없음** — 상황·자책이지 효과 단정이 아니다                | **거의 그대로 채택**                                                       | **C-3 제목**          |
| 「직원만 잘 뽑아도 연매출 10억은 껑충!!!! 내 직원 사주 고르자」 | ①효과 단정(실증 불가) ②「뽑아도·고르자」=채용 판단(§3-1 ①) | 「**사람 하나 잘못 들여 회사가 휘청인 적, 있으신가요**」 → 최종 제목은 C-4 | **C-4 서브카피 계열** |

**변환 규칙 3줄**

1. **숫자 성과를 감정으로 바꾼다** — 「연매출 10억」 → 「회사가 휘청인 적」
2. **명령을 질문으로 바꾼다** — 「고르자」 → 「왜 늘 같은 데서 부딪힐까」
3. **미래 보장을 과거 경험으로 바꾼다** — 「~하면 오른다」 → 「~한 적 있으신가요」

금지: 숫자 성과(10억·3배·연봉 n%) · 보장 어휘(반드시·확실히·성공·대박) · 비교우위(최고·유일·1위) ·
앱 공통 금지어 5종(**매일·무제한·평생·모두 이용·정액**) · 의료/법률/투자 판단 어휘.

🔴 **기존 테스트는 이 세트를 지켜주지 않는다.** `membership-benefits.test.ts` 의 금지어 검사는
`membership-benefits.ts` 가 생성한 문자열만 훑는다(전역 grep이 아니다).
→ 마스터 §6-2의 `themes.test.ts` 에 **같은 BANNED 배열 + 본 세트 전용 금지어**를
제목·서브카피·라벨·고지문 전량에 건다.

### 3-4. 이 세트 전용 — 「결론을 주지 않는다」 규율

직장·재물 테마 8종 중 **4종(C-1·C-5·C-4·W-3)이 양자택일 질문**이다. 후킹은 양자택일로 하되
**답은 양자택일로 주지 않는다.** 대신 **「지금 힘든 것이 구조인가 시기인가」로 가른다.**

| 테마 | 사용자가 기대하는 답 | 실제로 주는 답                                   |
| ---- | -------------------- | ------------------------------------------------ |
| C-1  | 「이직해라/버텨라」  | 지금 답답한 게 **자리 문제인지 시기 문제인지**   |
| C-5  | 「접어라/버텨라」    | 눌린 것이 **구조인지 시기인지** + 결이 바뀌는 때 |
| C-4  | 「이 사람 괜찮나」   | **어디서 부딪히고 어떻게 말하면 통하는지**       |
| W-3  | 「동업해라/마라」    | **깨진다면 어느 자리에서 깨지는지**              |

🔴 **표시와 내용이 어긋나면 표시광고 위험이자 환불 민원의 씨앗이다**(연애 세트 L7에서 확립한 규율).
그래서 각 테마의 **서브카피가 답의 축을 미리 밝힌다** — 「골라드리지 않습니다, 갈라드립니다」.

### 3-5. 상대방 동의 — PAIR 2종(C-4·W-3) 공통

연애 세트 §4-1이 세운 필수 3종을 **그대로** 승계한다. 직장 관계라고 완화하지 않는다.

1. 인연 등록 시 1회 고지 + 체크(§3-1 ②의 문안과 합침)
2. 결과 최상단 «관계의 결» 선언: 「이 풀이는 두 분의 생년월일이 만드는 **기운의 결**을 읽은
   것입니다. 상대의 능력이나 마음을 평가한 것이 아닙니다.」
3. 결과 최하단 «대화 실마리» 3문장 — 판정을 결론이 아니라 **질문으로 되돌린다.**
   🔴 직장 세트에서는 이 블록이 **윤리 장치이자 법적 장치**다. 「판정을 근거로 사람을 평가」에서
   「대화를 시작」으로 행동을 돌리는 것이 §3-1의 실질적 집행이다.

### 3-6. 취약 이용자 — C-5(접을까 버틸까) 추가 규율

폐업을 고민하는 사람은 **부채와 생계가 걸린 상태**로 이 카드를 누른다.

- 「접으세요」도 「버티세요」도 **양방향 금지.**
- 채무·회생·파산·대출 어휘 금지(법률·금융 자문 경계). 상환 계획·자금 조달 조언 금지.
- 🔴 **재구매 유도 배너 금지** — 같은 테마 재분석 CTA를 붙이지 않는다(캐시 7일 유지).
- 결과 하단에 **「둘 다 아님」 경로**가 반드시 존재해야 한다(§5 C-5). 없으면 항상 불안을 파는
  구조가 되고, 그건 표시광고법 이전에 상품으로서 거짓이다(풍수 테마2에서 확립).

### 3-7. 🔴 허브 자동 호출 금지

9차에 「오늘의 운세 카드가 마운트마다 Gemini 생성」 사고가 났다(`35fc061` 로 수복).
**테마 카드는 제목·썸네일만 렌더하고, AI는 버튼 진입에서만 부른다.** 목록 페이지·허브 와이드
카드 어디에서도 `analyzeTrendAction`·`analyzeWealth`·테마 액션을 호출하지 않는다.

### 4-2. 3층 구조 — 이 세트에서 무엇이 어느 층인가 (마스터 §5-1)

```
L1  결정론 (기존 엔진, 순수 함수)      lib/saju-engine/* — 새로 안 만든다
      ↓ 테마별로 필요한 필드만 뽑는다
L2  판정 (새로 쓰는 유일한 코드)        lib/domain/theme-fortune/rules/{id}.ts
                                        순수 TS · 30줄 내외 · 단위테스트 필수 · 테마당 1개
      ↓ ThemeVerdict 로 확정
L3  서술 (AI)                          계산 금지. 확정 사실을 문장으로만 만든다.
```

**L3에 박는 고정 지시문**(마스터 §5-1, 8종 공통·문자열 그대로):

```
아래 [확정 판정]은 이미 계산이 끝난 값이다. 다시 계산하지 말고, 숫자를 새로 만들지 말고,
판정과 어긋나는 서술을 하지 마라. 당신의 일은 이 판정을 사람의 말로 풀어 쓰는 것뿐이다.
```

**`analysisType` 은 새로 만들지 않는다**(마스터 §5-4 — `getAnalysisTypeGuide()` 가 Record 전수
매핑이라 늘수록 유지비가 붙는다). 기존 유니온만 쓴다:

| 테마            | analysisType    | 근거                                          |
| --------------- | --------------- | --------------------------------------------- |
| C-1·C-2·C-3·C-5 | `TREND_CAREER`  | 「직장/사업운」 — 가이드가 이미 이 결이다     |
| W-1·W-2         | `WEALTH_DEEP`   | 정재/편재 서술 규율이 이미 프롬프트에 있다    |
| C-4·W-3         | `COMPATIBILITY` | 2인 — `focus-groups` 가 문체·금지 소재를 준다 |

테마 고유 지시는 **`additionalContext` + `outputFormatGuide` 두 인자로만** 주입한다.

🔴 **AI가 만든 월(月)을 그대로 내보내지 않는다.** 파싱 후 서버에서 `ThemeTiming.months` 부분집합인지
검증하고, 어긋나면 L2 값으로 덮는다(마스터 §5-4 마지막 줄). 조용히 틀린 달을 내보내지 않는다.

### 4-3. 썸네일 — 드라마 스틸 컷 (마스터 §10)

CEO 지시가 「드라마 제목·썸네일 만들듯이」이므로 **마스터 §10-2의 드라마 스틸 문법**을 쓴다.
(자매 문서 중 관상은 수묵 초상, 풍수는 무인물 정물, 연애는 사물 정물이다 — 본 세트만 **인물이 있는
장면**이다. 직장·재물의 통증은 «사람이 어떤 자리에 있는가»로만 그려진다.)

| 용도               | 크기     | 파일                                  |
| ------------------ | -------- | ------------------------------------- |
| 허브 와이드 (16:9) | 1024×576 | `public/theme-fortune/{id}-wide.webp` |
| 목록 타일 (4:3)    | 512×384  | `public/theme-fortune/{id}-tile.webp` |

```js
const STYLE =
  'warm painterly watercolor illustration, soft K-anime aesthetic, gentle golden rim light and subtle warm glow, rich detail'
const BG_SCENE = 'deep warm dark background, no text, no letters, no watermark'

const posterPrompt = (desc) =>
  `Cinematic still from a Korean drama, 16:9 wide framing: ${desc}. ${STYLE}, ` +
  `camera at eye level, shallow depth of field with the background softly blurred, ${BG_SCENE}`
```

**작성 규칙**(위반하면 캐릭터 시트가 나오거나 방향이 뒤집힌다 — 실측된 실패 패턴)

1. **메타 지시문 금지** — `CRITICAL` `must NOT` `IMPORTANT` `do not` 를 쓰지 않는다.
2. **관찰 가능한 사실만.** 「지쳐 보이는」(해석) ✗ → 「책상에 팔을 괴고 모니터를 응시하는」(관찰) ○
   설명이 안 먹히면 문장을 늘리지 말고 **관찰 사실 1개를 추가**한다.
3. **방향을 반드시 명시** — `facing right`, `left of center`. 생략하면 회차마다 뒤집힌다.
4. **얼굴은 몸을 따라 돈다고 못박는다** — `head turned to follow the body`.
5. 문구·간판·숫자·로고·실존 인물을 넣지 않는다.
6. 🔴 **제목 글자를 이미지에 굽지 않는다**(마스터 §10-1) — 법적 사유로 문구를 빨리 고쳐야 할 수
   있고(9차 정정처럼), i18n 때 전량 재생성이 된다. 제목은 HTML 텍스트 오버레이.

🔴 **검수는 육안이 정본**이고 **실제 렌더 크기(허브 448px 폭)**에서 한다. 원본 1024에서 보면 전부
좋아 보인다. 교체 시 **파일명 버전업**(`{id}-wide-v2.webp`) — 덮어쓰기는 폰 캐시가 옛 그림을 쓴다.

### 4-4. 🔴 인물 묘사 규율 — 본 세트 전용

인물이 들어가는 순간 **차별 위험**이 생긴다. 직장·재물은 특히 그렇다.

- **성별·연령을 제목·서브카피에 쓰지 않는다.** 썸네일 인물도 특정 성별로 고정하지 않는다
  (`a person` 으로 쓰고, 세트 전체에서 인물의 성별이 한쪽으로 쏠리지 않게 배분한다).
- 직급·업종을 시각적으로 단정하지 않는다(정장=관리자 같은 도식 회피).
- 「사장」이 등장하는 C-3은 **사람이 아니라 빈 자리**로 그린다(§5 C-3 ③).

### C-1. 「나갈까 말까, 벌써 세 번째」 — `leave-or-stay`

직장 계열 최대 모수. 이직 충동 경험 94.9%(R3)에 이직 보류 사유 2위가 **「시기 문제」**(R2)다 —
사람들이 이미 «때»를 묻고 있다. 🔴 그리고 R1이 이 테마의 설계를 뒤집었다:
**후회하는 쪽은 나간 사람(25.6%)이 아니라 안 나간 사람(57.0%)이다.**
그렇다고 「나가세요」는 §3-4 위반이다 → **답을 주지 않되, «머무는 것도 선택»을 판정에 넣는다.**

1. **후킹 제목**: 「**나갈까 말까, 벌써 세 번째**」
2. **서브카피**: 고르라고 하지 않습니다. 지금 답답한 게 자리 탓인지 때 탓인지 갈라드립니다.
3. **썸네일**: 사무실 창가에 선 사람이 오른쪽 창밖을 본다. 책상엔 아직 안 닫은 노트북과 식은
   커피, 의자 등받이엔 코트. — **떠남의 물건과 머무름의 물건이 한 화면에** 있다.
   ```
   Cinematic still from a Korean drama, 16:9 wide framing: a person standing beside a large
   office window left of center, facing right toward the glass, head turned to follow the body,
   an open laptop and a cup of cold coffee left on the desk behind them, a long coat hanging
   over the back of the desk chair, late afternoon light coming through the window from the right
   ```
4. **타깃**: 재직 중 20~40대. 「그만두고 싶은 게 일 때문인지 사람 때문인지 모르겠다」 구간.
   연말·연초(평가·연봉협상 직후 — R4: 협상 후 퇴사 충동 52.9%)와 3월에 수요가 몰린다
   → 마스터 §6-3 v1.5 **시즌 가중의 1순위**.
5. **입력**: **본인 생년월일시만**(`v_destiny_targets` self). 회사·직무·연봉을 묻지 않는다.
   🔴 회사명·직무를 입력받는 순간 그 값이 결과에 인용되고, 그때부터 이 도구는 «직장 진단»으로
   읽힌다. **입력 최소화가 곧 법적 방어다.**
6. **풀이 설계** — 엔진 `buildSajuContext` ×1 + `calculateYearlyFortune` ×2개년(올해·내년)

   | L1 결정론 (코드가 확정)                                                                                                                 | 출처(기존 코드)                      |
   | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
   | ⓐ **조직 압력** — `sipseong.distribution` 정관+편관 개수, 편관 비중, `strengthAssessment`                                               | `sipseong.ts analyzeSipseong`        |
   | ⓑ **나가려는 힘** — 식신+상관 개수 + `sinsal` 의 **역마살** 유무(`SINSAL_MODERN.역마살`)                                                | `sipseong.ts` · `sinsal-extended.ts` |
   | ⓒ **올해·내년의 문** — `calculateYearlyFortune(ctx, y).categories` 중 **`직업운`** score·trend + `yongsinAffinity` + `sipseongRelation` | `woon-calculator.ts`                 |
   | ⓓ **열리는 달 / 막히는 달** — `keyOpportunityMonths` · `keyCautionMonths`                                                               | 동                                   |
   | ⓔ **관성이 흔들리는 자리** — `interactions[]` 중 관성 기둥과 맺는 충·형(`pillarSource`)                                                 | 동                                   |
   | ⓕ **결이 바뀌는 나이** — `analysis.daeun` 현재 구간 잔여 + 다음 대운 오행이 용신 쪽인지                                                 | `saju-analysis.ts calculateDaeun`    |
   | ⓖ **룰 히트** — `TAHYANG_02`(잦은 이동·해외운) · `LEGAL_01/02`(관재구설) · `CAREER_03`(무역·창업 적성)                                  | `rule-base.ts evaluateAllRules`      |

   **L2 판정** (`rules/leave-or-stay.ts` — 순수 함수 1개, 30줄 내외)

   | 지표 key        | 라벨            | 계산                                    | `basis` 예시                          |
   | --------------- | --------------- | --------------------------------------- | ------------------------------------- |
   | `gwan_pressure` | 「눌리는 힘」   | ⓐ 관성 개수 × 편관 가중 ÷ 신강약 보정   | 「편관 2 · 정관 1 — 여덟 글자 중 셋」 |
   | `siksang_pull`  | 「나가려는 힘」 | ⓑ 식상 개수 + 역마살 가산               | 「상관 2 · 역마살 — 밖으로 도는 결」  |
   | `year_gate`     | 「올해의 문」   | ⓒ 직업운 score + `yongsinAffinity` 보정 | 「세운 정관이 용신과 합」             |
   - **판정 라벨 4택** — 앞 두 축 밴드의 **2×2 고정 매핑표**(새 계산 아님):

     |                    | 나가려는 힘 낮음                   | 나가려는 힘 높음       |
     | ------------------ | ---------------------------------- | ---------------------- |
     | **눌리는 힘 높음** | 「**버티는 결**」                  | 「**밀려나는 결**」    |
     | **눌리는 힘 낮음** | 🔴「**자리보다 다른 데 있는 결**」 | 「**스스로 뜨는 결**」 |

     🔴 좌상단 칸이 이 테마의 양심이다 — **「직장 문제가 아닐 수 있다」는 답이 반드시 존재해야
     한다.** 그 판정이 나오면 화면은 결론 대신 고민상담으로 닫는다.
     그리고 「버티는 결」은 **패배가 아니라 선택**으로 서술한다(R1이 만든 함정 — 남는 쪽을
     실패로 그리면 그 순간 이 상품이 이직을 권한 것이 된다).

   - `timings`: 기회 = ⓓ `keyOpportunityMonths` ∩ (ⓒ trend `good` 이상) / 주의 = `keyCautionMonths` ∪ ⓔ 충 발생 월
   - `ruleHits`: ⓖ / `pastHint`: 직전 세운에서 관성이 충을 만난 해 → 「그 무렵 자리에 변동이
     있었을 것」(기존 `trend.ts` pastHint 지시문의 결을 그대로 승계)
   - **L3 계약**: `TREND_CAREER` + `ThemeVerdict` JSON + 🔴 프롬프트 상수 —
     「이직을 권하거나 만류하지 마라. 무엇이 자리에서 오고 무엇이 시기에서 오는지만 설명하라.
     연봉·처우·회사 규모·업종 전망을 언급하지 마라.」

7. **결과 화면**: ①히어로 → **«갈라드립니다» 배지** → ②한 줄 답 → ③지표 3 + **판정 라벨 2×2
   카드** ← 감탄 지점 → ④지금 상황 → ⑤12개월 띠(열리는 달 금색·막히는 달 회색) → ⑥할 일 3 →
   ⑦되짚기 → ⑧다음 걸음(**C-2 · C-4**) → ⑨`ServiceDisclaimer`
8. **복채**: **2만냥** — `buildSajuContext` 1회 + 세운 2회 + AI 1회. 사주(2만냥)와 같은 무게.
9. **법적·윤리 체크**:
   - 🔴 **양방향 금지**(§3-4) — 「이직하세요」도 「참으세요」도 안 된다. 프롬프트 상수로 박는다.
   - 🔴 **효과 단정 금지** — 「이직하면 연봉이 오릅니다」·「이 달에 옮기면 잘 풀립니다」(X) →
     「이 달은 사람이 움직이는 결이라 **이야기를 꺼내볼 만합니다**」(O)
   - 🔴 **노동 상담이 아니다** — 부당해고·권고사직·실업급여·근로계약 어휘 금지. 그 질문은 공적 창구다.
   - 🔴 **R1을 화면에 인용하지 않는다.** 「안 나간 사람의 57%가 후회한다」를 결과에 적는 순간
     이 풀이는 이직을 권한 것이 된다. 통계는 테마를 만든 이유이지 결과의 근거가 아니다(§2-6 규율).
   - 회사·상사를 특정해 평가하는 서술 금지(상대 정보를 받지 않으므로 구조적으로 불가).
   - 금지어 0. 강화 고지 없음(`ServiceDisclaimer` 만).

### C-2. 「그만두면, 그다음은 뭘 하지」 — `what-next` ★무료 미끼(career)

C-1의 자연스러운 다음 칸. **엔진 원가가 가장 싸서 무료로 쓴다** — `buildSajuContext` 1회로
끝나고 세운을 돌지 않는다. 동시에 **공유가 가장 잘 되는 형태**(적성 라벨)라 유입구로 맞다.
R14(폐업 후 취업 41.4 / 멈춤 29.3 / 재창업 26.9)가 보여주듯 이 질문의 답은 **세 갈래로 갈린다.**

1. **후킹 제목**: 「**그만두면, 그다음은 뭘 하지**」
2. **서브카피**: 하고 싶은 게 없는 게 아니라, 아직 이름을 못 붙였을 뿐입니다.
3. **썸네일**: 밤 책상 앞에 앉은 사람이 몸을 오른쪽으로 돌려 **세 갈래로 갈라진 복도**를 본다.
   책상엔 뚜껑 열린 만년필과 아무것도 안 쓴 종이. (세 갈래 = R14의 세 갈래)

   - **구조적 / 한시적 배지**(C-4와 동일 분류 재사용).
   - `timings`: ⓔ 기준 「**두 사람 다 눌리는 해**」(주의)만 낸다.
     🔴 **「계약·투자에 좋은 시기」를 만들지 않는다** — BUSINESS 질문 ⑤를 시기 산출로 구현하지 않고
     **「무엇을 문서로 남길 것인가」**라는 준비 항목으로 바꾼다.
   - `pastHint`: `null`(BUSINESS 군도 `generatePastRetrograde: false`).
   - **L3 계약**: `COMPATIBILITY` + `FOCUS_GROUPS.BUSINESS`(연애 소재 금지 + **「리스크를 솔직하게
     지적하라」가 이미 스펙에 있다** — 40점 이하 경고 규칙 포함) + 🔴 테마 고유 `forbidden`:

     상대의 정직성·신용을 판정하지 마라.」

7. **결과 화면**: ①히어로 → **강화 고지 박스 2겹**(사업 결정 + 투자 자문 아님) →

   🔴 총점 링 없음(C-4와 동일 — 「몇 점이면 동업」이라는 오독을 막는다).

## 6. 복채 단가 — 마스터 §7-1 배정 규칙의 적용

마스터가 정한 3단(**0 / 2만냥 / 3만냥**)을 그대로 쓴다. **5만냥은 쓰지 않는다** — 같은 값이면
재물 심층(5만냥)과 구분이 되지 않는다.

**배정 규칙 한 줄**(마스터 §7-1 파생):

> 엔진 1회 + AI 1회 + **타임라인 없음** = **무료(미끼)** ·
> 1인 사주 전체 골격 9섹션 = **2만냥** · 2인 궁합 엔진 + 관계 편집 = **3만냥**

| 테마 | 엔진 호출                                          | 단가  | 근거                                                    |
| ---- | -------------------------------------------------- | ----- | ------------------------------------------------------- |
| C-2  | `buildSajuContext` ×1                              | **0** | 세운 0 · `timings` 비움 · 9섹션 중 5개 — career 미끼    |
| W-2  | `buildSajuContext` ×1                              | **0** | 동. **`timings: []` 이 설계상 고정** — wealth 미끼      |
| C-1  | ×1 + `calculateYearlyFortune` ×2개년               | 2     | 사주(2만냥)와 같은 무게                                 |
| C-3  | ×1 + 세운 ×1개년                                   | 2     | 동                                                      |
| C-5  | ×1 + 세운 ×3개년                                   | 2     | 🔴 세운 3회는 **결정론 계산이라 AI 호출이 늘지 않는다** |
| W-1  | ×1 + 세운 ×1개년                                   | 2     | 동                                                      |
| C-4  | ×2 + `calculateCompatibility` ×1 + 월운 ×2         | 3     | 2인 엔진 + 관계 편집(마스터 §7-1 «관계» 단)             |
| W-3  | ×2 + `calculateCompatibility` ×1 + 세운 ×2인×2개년 | 3     | 동                                                      |

🔴 **등급을 가르는 것은 함수 호출 수가 아니라 «AI 호출 수 + 사람 수»다.** 결정론 계산은 CPU만
쓴다. C-5가 세운을 3번 돌아도 2만냥인 이유가 이것이다.

🔴 **표시 = 실차감 원칙**: 단가는 반드시 `feature-costs.ts` 에 키를 추가해 파생시킨다.
`themes.ts` 에 숫자를 직접 쓰면 그 순간 표시 가격이 6곳에서 어긋났던 옛 사고가 재발한다.
새 키를 만들 거면 **`FeatureCostKey` · `FEATURE_COST` · `MISSION_CATEGORY_TO_COST_KEY` · 실차감
호출부를 동시에** 고쳐야 표시=실차감이 유지된다.

> ⚠️ **단가는 확정값이 아니다.** CEO가 2026-08-12 「**메인 테마운세 기획 후 가격을 전부 정리**」
> 하라고 지시했다. 이 §6은 확정가가 아니라 **가격 개편의 입력값**이다(§9 결정 2번).
