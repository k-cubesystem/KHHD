### 1.1 결정론 지표 — 사진 1장에서 나오는 14개 판정

| 층             | 항목                                                     | 값                         | 출처                                       |
| -------------- | -------------------------------------------------------- | -------------------------- | ------------------------------------------ |
| 오관(五官) 5   | `ears` `eyebrows` `eyes` `nose` `mouth`                  | 좋음/보통/주의 + 설명      | `[[EARS:]]` 등 태그 → `parseFeatureTag`    |
| 삼정(三停) 3   | `upperStop`(이마) `middleStop`(눈·코) `lowerStop`(입·턱) | 좋음/보통/주의 + 설명      | `[[UPPER_STOP:]]` 등                       |
| 부위(部位) 6   | `forehead` `eyes` `nose` `mouth` `ears` `chin`           | + 관장 운세영역 + 개운조언 | `[[PART_*]]` → `parsePartFeature`          |
| 기색(氣色)     | `gisaekReading` / `gisaekAdvice`                         | 한 줄 + 관리 조언          | `[[GISAEK:]]` → `gisaek-parse.ts`          |
| 첫인상         | `firstImpression`                                        | 한 문장                    | `[[FIRST_IMPRESSION:]]`                    |
| 오행형(五行形) | `木火土金水` + 근거                                      | 5택1 + 사유                | `[[ELEMENT_FORM:]]` → `element-form.ts`    |
| 종합점수       | `score` 0~100                                            | **순수 함수**              | `computeFaceScore` (`analysis/scoring.ts`) |
| 칭호           | 한자 4자 + 한글 + 부연                                   | **순수 함수**              | `titles.ts` (category×goal×band 매트릭스)  |
| 개선 우선순위  | 상위 3 zone + `modernFix` + `impact`                     | **순수 함수**              | `calculateImprovementPriority`             |
| 사주 교차      | `sajuSynergy` (일간 기반)                                | **순수 함수**              | `buildFaceSajuSynergyText`                 |
| 나이대 운      | `ageFortuneMap.youth/middle/senior`                      | 텍스트                     | `AGE_FORTUNE_ZONES`                        |
| 가족 닮은꼴    | 부위별 일치 → 「이어받은 것」 서사                       | **순수 함수**              | `buildFamilyResemblance` (AI 호출 0)       |

`computeFaceScore`는 **부위(가중3) > 오관(2) > 삼정(1)** 의 가중 평균을
`17.75 + 76.25·w` 로 편다. 즉 **14개 assessment 를 어떻게 다시 가중하느냐가
곧 새 테마**다. 새 모델도, 새 사진도 필요 없다.

### 1.2 사진은 **저장되지 않는다** — 재사용 대상은 판정이지 사진이 아니다

개인정보처리방침(`app/privacy/page.tsx`)에 명문화되어 있다:

> 얼굴·손바닥·실내 사진 — **분석 완료 후 즉시 삭제(서버 미보관)**

그래서 이 기획의 아키텍처가 결정된다.

- ❌ 「저장된 사진으로 테마 8개를 더 돌린다」 → **불가**(사진이 없다. 방침 개정은 최악의 선택)
- ✅ 「저장된 **판정**(`analysis_history.result_json`)에서 테마를 파생한다」 → **가능·이미 선례 있음**

선례가 `app/actions/ai/samhap.ts` 다. `latestReading(FACE|HAND|FENGSHUI)` 로
과거 판정을 끌어와 종합 리포트를 만든다 — **이미지 재업로드 없이**. 테마도 같은 길을 간다.

### 1.4 🔴 실측 중 발견한 함정 3가지

`app/protected/analysis/theme/[type]/page.tsx` 는 **점수 85가 하드코딩**되어 있고
AI 호출도 복채 차감도 없다. "현재 재물운의 기운이 매우 좋습니다"가 **누구에게나 똑같이** 나온다.
그런데 `AnalysisDashboard.tsx` 의 재물/애정/직장/학업/부동산 5칸이 **전부 이 목업으로 링크**되어 있다.
→ 표시광고법 관점에서 이미 위험(측정하지 않은 수치를 측정값처럼 표기).
**인기테마운세 착수 시 이 라우트의 처리(교체/폐기)를 첫 항목으로 잡아야 한다.**

**② 무료 등급 기록 상한 10개가 테마를 잡아먹는다.**
`app/actions/user/history.ts` 는 저장 시 `storage_limit` 초과분을
**즐겨찾기가 아닌 오래된 것부터 삭제**한다(무료 10개). 테마 결과를 그대로
`analysis_history` 에 쌓으면 **테마 8개가 원본 관상 판정을 밀어낸다** —
파생의 근거가 스스로 지워지는 구조다.
→ 처방(§5.4): 원본 FACE 는 자동 즐겨찾기 고정 + 테마 파생본은 **원본 참조로만 보관**.

**③ 「채용·승진 적합도」는 이미 한 번 삭제된 문구다.**
`a599a2f`(2026-08-12) 에서 `/business` 의 채용·승진 적합도가 **채용절차법 위험**으로
전면 삭제됐고, HANDOFF 에 "되살릴 때 법무 확인 먼저"가 박혀 있다.
→ 테마 3(면접)은 **합격 예측·적합도 판정을 하지 않는다**. §6-3 참조.

## 3. 규율 — 이 테마 세트가 지켜야 할 선

### 3.1 톤: **판정이 아니라 해석**

관상은 외모 평가와 한 뼘 거리다. 문장 하나가 서비스를 죽인다.

| 금지                            | 대체                                                  |
| ------------------------------- | ----------------------------------------------------- |
| "코가 낮아 재물이 없습니다"     | "재물을 **모으는 방식**이 코에 드러납니다 — 당신은 …" |
| "인상이 사나워 손해를 봅니다"   | "당신의 인상은 **먼저 신뢰를 요구하는** 쪽입니다"     |
| "노안입니다"                    | "**중정(中停)이 이른 얼굴** — 일이 일찍 오는 상"      |
| "이 얼굴은 면접에서 불리합니다" | "면접관이 **먼저 읽는 것**은 당신의 이마입니다"       |
| "성형하면 재물운이 열립니다"    | **전면 금지**(§3.4·자매문서)                          |

문장 규칙 3개:

1. **주어는 「인상」이지 「얼굴」이 아니다.** 인상은 읽히는 것이고 바꿀 수 있다. 얼굴은 타고난 것이다.
2. **모든 「주의」 판정에는 반드시 그 부위의 강점 문장이 앞선다.** (강점 → 유의 → 처방 순서 강제)
3. **비교급 금지.** 「~보다 낫다/못하다」, 「평균 이하」, 백분위 표기 금지. 점수는 절대 척도로만.

### 3.2 차별 금지 (성별·나이·인종)

- 특정 이목구비 형태를 **열등하게** 서술하지 않는다. 쌍꺼풀 유무·코 높이·피부색·얼굴 크기는
  **길흉의 근거로 쓰지 않는다.** 전통 관상의 「기색(氣色)」은 피부 **상태**(윤기·혈색)이지
  **피부색**이 아니다 — 프롬프트에 이 구분을 명시한다.
- 성별에 따라 다른 덕목을 요구하지 않는다(예: 여성에게 「순한 상」을 권하는 문장 금지).
- 나이에 대한 가치판단 금지. 「동안=좋음」 프레임을 쓰지 않는다(테마 4가 정면으로 다룬다).
- **금지어 회귀 테스트를 확장**한다. `membership-benefits.test.ts` 의 `BANNED` 패턴을 그대로
  본떠 `theme-face-copy.test.ts` 를 신설:
  `['못생', '추한', '천한 상', '흉상', '노안', '호구', '평균 이하', '수술', '시술', '성형']`

### 3.3 🔴 미성년자 사진 — **현재 정책이 없다. 이것이 이 기획의 최대 공백이다.**

실측 결과:

- `app/terms/page.tsx` 와 `story-trust.tsx` 에 **「만 14세 미만 가입 불가」만** 있다.
- **업로드되는 얼굴의 나이에 대한 정책은 어디에도 없다.**
- 그런데 관상은 `target` 파라미터로 **가족 구성원 분석을 정식 지원**한다
  (`family_members` 조회 → `persistImageAnalysisHistory(targetId)`).
  즉 **부모가 자녀 사진을 올리는 경로가 이미 열려 있다.**

이건 「있으면 좋은 것」이 아니라 **구멍**이다. 아동의 얼굴에 「재물운 주의」가 붙는 순간
서비스가 방어할 논리가 없다. 착수 전 아래를 정해야 한다(§11 CEO 결정 1번).

권고안:

| 항목        | 권고                                                                                                                                           |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 연령 하한   | **만 14세 미만 얼굴 분석 차단** — 가입 기준과 같은 선                                                                                          |
| 판정 방법   | `family_members.birth_date` 는 **이미 저장되어 있다**(사주 교차분석이 쓰고 있음). 서버에서 나이를 계산해 차단 — 자기신고 UI 불필요             |
| 본인 업로드 | 업로드 화면에 "**본인 또는 동의를 받은 성인**의 사진만" 고지 + 체크                                                                            |
| 테마 적용   | 미성년 대상은 **관상 원본도 테마도 전부 차단**(부분 허용은 경계가 흐려진다)                                                                    |
| 서버 게이트 | 🔴 화면만 감추면 안 닫힌다 — `'use server'` 는 공개 엔드포인트(오픈이벤트 폐기 때의 교훈, `a599a2f`). `analyzeFaceForDestiny` 첫 줄에서 막는다 |

### 3.4 성형·의료 언급 — 이미 프롬프트가 막고 있다. 그 선을 테마에도 그대로.

현행 `face_reading` 프롬프트 말미에 이미 있다:

> ※ **의학적/성형 관련 조언은 절대 하지 마세요.**

`calculateImprovementPriority` 의 `modernFix` 도 전부 비의료다 —
메이크업·수면·마사지·헤어·자세. **이 선을 테마 프롬프트에도 그대로 복제**하고,
테스트로 고정한다(§9). 성형 연계 수익모델은 이 선을 **넘지 않는 자리에서만** 성립한다
(자매 문서 `PLAN-beauty-affiliate-v1.md`).

### 3.5 앱 공통 금지어

`매일` · `무제한` · `평생` · `모두 이용` · `정액` — 테마 카피에도 동일 적용.
효과 단정(「~하면 재물이 들어옵니다」) 금지 → 「~라고 봅니다」 「~로 읽힙니다」.

## 4. 규격 — 8종 공통 (다른 기와 통일)

각 테마는 아래 9항목을 전부 갖는다. 하나라도 비면 미완성으로 본다.

1. 후킹 제목 2. 서브카피 3. 썸네일 컨셉 + 생성 프롬프트 초안
2. 타깃 5. 입력 6. **풀이 설계**(결정론/AI 경계) 7. 결과 화면
3. 복채 단가 9. 법적·윤리 체크(**상처 지점 + 완화 문구** 포함)

### 4.1 썸네일 공통 규격

기존 허브 아이콘 `public/icons/hub/gwansang.webp` 가 정본 어휘다 —
**수묵 담채 옆얼굴 + 얼굴 위 금색 성좌선 + 투명 배경 + 갈금(褐金) 팔레트**.
테마 8종은 이 어휘를 **깨지 않고** 변주한다.

| 항목      | 값                                                                                |
| --------- | --------------------------------------------------------------------------------- |
| 형식·크기 | `webp` · 512×512 · 투명 배경 · 20KB 내외(기존 11종과 동일)                        |
| 경로      | `public/icons/theme/face/<code>.webp` (허브 아이콘과 분리 — 교체 주기가 다름)     |
| 팔레트    | `#C9A84C`(금) · `#A8903F` · `#9E2B2B`(주) 점 하나 · 먹 `#0A0A08` 농담             |
| 금지      | 실존 인물 얼굴 · 사진 · 성형 전후 대비 구도 · 화살표/수술선 · 텍스트              |
| 🔴 캐시   | 교체 시 **반드시 파일명 버전업**(`-v2`). 같은 이름 덮어쓰기 = 폰이 옛 그림 재사용 |

**프롬프트 작성 규율**(`feedback_image_prompt_rules` 준수):

- 설명을 늘리지 말고 **관찰 가능한 사실을 하나 더한다**.
- **메타 지시문 금지** — `CRITICAL`, `must NOT`, `this should` 를 섞으면 캐릭터 시트가 나온다.
- **방향을 반드시 명시**한다(「오른쪽을 보는 옆얼굴」).
- 얼굴은 몸을 따라 돈다고 못박는다.

### 5.2 🔴 결정론과 AI의 경계 — 「AI가 알아서」는 반려

**규칙: 숫자·판정·부위 선택은 전부 순수 함수. AI 는 그 결과를 «말로 옮기는 일»만 한다.**

| 층                 | 주체                   | 산출                                         | 검증               |
| ------------------ | ---------------------- | -------------------------------------------- | ------------------ |
| ① 지표 추출        | 기존 관상 1회(AI+파서) | 14 assessment · 기색 · 오행형                | 이미 라이브        |
| ② **테마 축 점수** | **순수 함수(신규)**    | 테마별 2~3축 점수 0~100                      | **단위테스트**     |
| ③ **테마 칭호**    | **순수 함수(신규)**    | 한자 4자 + 한글 (score band)                 | **전 조합 스냅샷** |
| ④ **점등 부위**    | **순수 함수(신규)**    | 다이어그램에 켤 부위 목록                    | **단위테스트**     |
| ⑤ **처방 3개**     | **순수 함수(재사용)**  | `calculateImprovementPriority` 가중치만 교체 | 이미 테스트 있음   |
| ⑥ 서술             | AI(텍스트 전용)        | ②~⑤ 를 **입력으로 받아** 200~400자 서사      | 금지어 테스트      |

②의 축 점수는 `computeAnalysisScore(items)` 를 **그대로 재사용**한다 —
`{value, weight}` 배열만 테마별로 다르게 만들면 된다. 새 스케일 함수를 만들지 않는다.

```ts
// 예시(설계안 — 코드 아님). 테마마다 이 표 하나가 전부다.
const THEME_AXES = {
  firstImpression: {
    warmth: [
      { part: 'mouth', w: 3 },
      { part: 'eyes', w: 3 },
      { part: 'gisaek', w: 2 },
    ],
    trust: [
      { part: 'nose', w: 3 },
      { part: 'forehead', w: 3 },
      { part: 'ears', w: 1 },
    ],
    presence: [
      { part: 'eyebrows', w: 3 },
      { part: 'chin', w: 2 },
      { part: 'eyes', w: 1 },
    ],
  },
  // …
}
```

**AI 서술은 지표를 다시 «판정»하지 않는다.** 프롬프트에 축 점수와 부위 assessment 를
숫자로 넣고 "이 판정을 뒤집지 말고 풀어 쓰라"고 지시한다. 뒤집으면 같은 사진이
테마마다 다른 말을 하고, 그 순간 신뢰가 죽는다.

```

③ 사주 교차 (있을 때만 — 없으면 카드 자체를 렌더하지 않음)
```

## 12. 하지 않기로 한 것 (기록)

- **연예인 실명 닮은꼴** — 초상권·퍼블리시티권 + 외모 비교 서열화. 오행 5형으로 대체(테마 6).
- **채용 적합도·합격 예측** — 채용절차법. 이미 `/business` 에서 한 번 삭제된 문구다(§1.4③).
- **얼굴 사진 서버 보관** — 개인정보처리방침 명문과 충돌. 재사용은 **판정**으로 한다(§1.2).
- **테마별 이미지 재분석** — 같은 사진을 8번 부르는 것은 비용도 지연도 8배이고,
  같은 얼굴에 서로 다른 판정이 나와 신뢰가 죽는다.
- **성형 시술 권유·전후 시뮬레이션** — §3.4 및 자매 문서 결론.
