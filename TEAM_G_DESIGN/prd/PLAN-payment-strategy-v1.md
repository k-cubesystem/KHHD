# 해화당 결제 전략 기획 v1 (2026-07-13)

> 근거 조사: `docs/REPORTS/RESEARCH-payment-playstore-20260713.md` (Google Play 정책 + 국내 운세앱 + Toss 실무)
> 목적: "어떻게 운영할지" + "Play Store 출시 시 결제 구성" 의사결정.
> 현재: Next.js 웹 + Toss + 복채 단일통화(1복채=₩10,000) + 멤버십 일일한도(SINGLE10/FAMILY30/BUSINESS100만냥).

---

## 결론 (권장안)

**웹 우선 유지 + 전환/리텐션 장치 보강**. Play Store는 "유입 채널"로만, 결제는 웹으로 유도하는 하이브리드.

1. **채널**: 웹(Toss)을 주 결제 채널로 유지 — Google 수수료(26~30%)를 피하는 게 마진상 압도적. Play Store는 TWA로 올리되 **앱 내 디지털 판매는 하지 않고**(정책 회피 아님, 아예 판매 UI를 앱에서 빼거나 Play Billing 병행), 결제는 웹 계정으로 이어지게.
2. **가격 구조**: 복채를 **벌크 보너스 팩**으로 재설계(현행 1:1 균일가 → 5단 팩 + 첫구매 2배). 투명성은 유지하되 "많이 살수록 이득" 심리 도입.
3. **전환 퍼널**: 첫 복채 구매 2배 지급(48h 한정) + 리워드 광고 무료 복채 + 출석 스트릭 보너스.
4. **리스크 회피**: "TWA 안에서 몰래 Toss 아웃링크"는 **절대 금지**(앱 삭제 전례). Play 출시 시엔 Play Billing 정식 사용 또는 대안결제 정식 등록 중 택일.

## 1. 현행 진단

|                 | 강점                                       | 약점                                              |
| --------------- | ------------------------------------------ | ------------------------------------------------- |
| 복채 단일통화   | 1:1 투명 매핑 → 신뢰↑, 다재화 통합 UX 단순 | 벌크 보너스·첫구매 특전 없음 → 지불의향·전환 손해 |
| 멤버십 일일한도 | 예측가능 구독수익 + 하이브리드(업계 정석)  | 스트릭/리텐션 연계 약하면 상한효과 제한           |
| 무료 유입       | 오늘의운세·기본사주 무료(정석)             | 리워드 광고형 무료재화 퍼널 부재(전환 레버 놓침)  |

## 2. 채널 전략 (시나리오)

| 시나리오                       | 수수료                                    | 판단                                                     |
| ------------------------------ | ----------------------------------------- | -------------------------------------------------------- |
| **A. 웹 전용(현행)**           | Toss 0.6~4.3%만                           | ✅ 마진 최선. Play 정책 무관. **1순위**                  |
| B. Play Store + Play Billing   | 15~30%(2026 신규 적용 시 구독 10%+빌링5%) | 유입엔 좋으나 마진 타격. 가격 웹보다 20~30%↑ 필요        |
| C. Play Store + 대안결제(Toss) | 26%/11% + PCI-DSS·부정거래 API 개발       | 별도 P0 프로젝트. 실익은 신규 수수료 한국 적용 후 재계산 |

**권장**: A로 시작. Play 출시가 필요해지면 B(Play Billing 병행, 웹가 유지·앱가 인상) → 규모 커지면 C 검토.

## 3. 복채 팩 재설계 (제안 — 수치는 확정 전 실측)

| 팩                      | 웹(Toss)        | 앱(Google 26% 가정) | 장치      |
| ----------------------- | --------------- | ------------------- | --------- |
| 1복채 (첫구매 한정 2배) | ₩10,000         | ₩12,500             | 최초 전환 |
| 3복채                   | ₩29,000 (3%↓)   | ₩36,000             |           |
| 5복채                   | ₩47,000 (6%↓)   | ₩58,000             |           |
| 10복채                  | ₩90,000 (10%↓)  | ₩112,000            | "인기"    |
| 30복채                  | ₩255,000 (15%↓) | ₩318,000            | 고관여    |

- 현재 `price_bokchae` 단일가 → 팩 상품 테이블(수량+보너스+채널가) 도입 필요.
- 신위 등급 가격(1/2/3/4복채) 앵커 문제(PRD §5.5)와 함께 재결정.

## 4. 전환·리텐션 장치 (조사 근거)

1. **첫 구매 2배**(48h 배너) — 전환율 3~5배 근거.
2. **리워드 광고 → 무료 복채** — 광고시청자 결제전환 4~5배. (AdMob 등 도입 필요)
3. **출석 스트릭 보너스** — 현 일일출석(이미 구현)에 연속일 배수 + "스트릭 프리즈". Duolingo +14%p.
4. **멤버십 = 기본 배급 / 복채 = 초과·특별 리딩·부적/신위/테마** 역할 분리(현행 유지).

## 5. Play Store 대비 아키텍처

1. **복채 원장 단일 테이블** — 채널(Toss/PlayBilling/대안결제) 태그만 구분, 지급 로직 1곳 수렴(이중지급 방지).
2. 영수증 검증 분리(Play Developer API / Toss 웹훅) → 공통 "복채 지급" 서비스로 수렴.
3. 대안결제 채택 시 PCI-DSS·부정거래 신고를 **별도 P0**로. "복채" 전자금융거래법 선불수단 등록 여부 법무 검토.
4. 2026 신규 수수료 한국 적용 모니터링.

## 사용자 결정 필요

1. **채널 방향**: (a) 웹 전용 유지 (b) Play Store 병행 출시 목표 — 이게 정해져야 가격 이원화·아키텍처 확정.
2. **복채 팩 도입 여부 + 가격표** — 현행 균일가 유지 vs 벌크 보너스 팩. (신위 등급가 §5.5와 동시 결정 권장)
3. **첫구매 2배·리워드 광고·스트릭 보너스** 중 우선 도입할 것.
4. **법무 자문**: 복채 선불전자지급수단 등록 대상 여부(폐쇄형 예외 가능성).
