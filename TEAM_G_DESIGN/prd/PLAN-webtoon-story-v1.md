# 웹툰 「내 이야기」 · 댓글 기획서 v1

- 일자: 2026-08-01
- 지시: **"웹툰에 내 이야기 쓰기 버튼 만들어주고, 이야기가 선정되면 스토리로 제작해주는 — 고객의 스토리를 직접 써주는 기획해줘. 그리고 웹툰 각 화마다 댓글 달 수 있는 댓글 시스템도 구축해줘. 내 이야기 쓰기는 비공개로 청담해화당 이메일로 오게 하고, 이야기 제작을 위한 소통을 위해 연락처(카카오톡, 핸드폰번호, 성함) 비공개로 제작되며 선정 시 연락이 간다는 내용을 적어줘."**
- 상태: 구현·배포 완료 (메일 발송은 키 설정 대기)

---

## 0. 이 기획의 한 줄

**독자의 사연이 웹툰의 원료가 된다.** 우리가 지어낸 이야기보다 겪은 이야기가 강하고,
자기 이야기가 실린 사람은 그 웹툰을 떠나지 않는다.

---

## 1. 「내 이야기」 프로그램

### 1-1. 흐름

```
독자가 사연을 쓴다 → 비공개 접수(DB) → 운영자 알림(메일) → 읽는다 → 선정
   → 연락(성함·전화·카카오) → 어디까지 그려도 좋은지 합의 → 각색 → 연재 → 그 화에 댓글
```

### 1-2. 세 가지 약속 — **입력 위**에 있어야 한다

CEO 지시를 화면 문구로 옮긴 것이고, 셋 다 **보내기 전에** 보인다.
보내고 나서 알려 주는 것은 약속이 아니다(테스트가 위치까지 강제한다).

| 약속         | 화면 문구                                                                                                                   |
| ------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 비공개       | "보내신 사연은 공개되지 않습니다 — 청담해화당으로만 전해지고, 웹툰 어디에도 그대로 실리지 않습니다."                        |
| 연락처 용도  | "성함·연락처·카카오톡 아이디는 **이야기 제작을 위한 연락에만** 씁니다. 공개되지 않으며 **선정되신 경우에만** 연락드립니다." |
| 선정 후 절차 | "연락드려 어디까지 그려도 좋을지 함께 정합니다 — 이름·지명은 바꾸고, 원하지 않으시는 대목은 뺍니다."                        |

### 1-3. 각색 규칙 (제작 실무)

1. **실명·지명·직장은 반드시 바꾼다.** 사연 주인이 허락해도 바꾼다 — 주변 사람은 허락한 적이 없다.
2. **빼 달라는 대목은 뺀다.** 극적이어도 뺀다. 신뢰를 잃으면 다음 사연이 오지 않는다.
3. **결말을 미화하지 않는다.** 풀리지 않은 이야기는 풀리지 않은 채로 그린다.
4. **신위를 사연에 억지로 끼워 넣지 않는다.** 세계관은 배경이지 해결사가 아니다.
5. 완성 전 **당사자 확인**을 한 번 받는다. 연재 뒤에는 되돌릴 수 없다.

### 1-4. 보상 (CEO 결정 대기)

지금은 아무것도 약속하지 않았다 — 값을 정하지 않은 채 "사례하겠다"고 적으면 나중에 분쟁이 된다.
후보: 멤버십 이용권 / 복채 / 원화 액자 / 크레딧 표기(익명 가능). **§5 결정 대기 참조.**

## 2. 저장 구조 — 세 표의 공개 범위가 서로 다르다

이 기능의 가장 큰 위험은 **사연과 연락처가 공개 표에 섞이는 것**이다. 그래서 표를 셋으로 갈랐다.

| 표                          | 무엇          | 읽는 사람                            |
| --------------------------- | ------------- | ------------------------------------ |
| `webtoon_episodes`          | 회차          | 공개된 것만 **누구나**               |
| `webtoon_comments`          | 댓글          | 지워지지 않은 것만 **누구나**        |
| `webtoon_story_submissions` | 사연 + 연락처 | **오직 본인**(운영자는 service_role) |

- 사연 표에는 **공개 select 정책이 없다.** 쓰기 정책도 없다(접수는 RPC 전용 — 하루 상한 우회 차단).
- 댓글 insert 정책에 `auth.uid() = user_id` 를 걸었다 — 없으면 남의 이름으로 쓸 수 있다
  (2026-07-31 소원 사칭 삽입 P0 와 같은 구멍이라 처음부터 닫았다).
- 같은 정책이 **미공개 회차에 댓글 다는 것**도 막는다.
- 내 사연 목록에는 **연락처 컬럼을 싣지 않는다** — 접수 확인 화면에서 어깨너머로 읽히는 것까지 막는다.

---

## 3. 메일 알림 — **알림 층**이지 접수가 아니다

⚠️ 순서가 규율이다: **저장 → 알림**. 알림 실패로 접수를 되돌리면 사람이 오래 쓴 글이 사라진다.

⚠️ **메일 본문에 사연 원문과 연락처를 싣지 않는다.** 메일은 전달 경로가 길고(중계·스팸함·포워딩)
한 번 나가면 회수할 수 없다. 메일은 "무엇이 들어왔는지"만 알리고 내용은 DB 한 곳에만 둔다.

메일 본문:

```
웹툰 「내 이야기」가 한 건 접수되었습니다.

접수번호 : {uuid}
접수시각 : {iso}
사연길이 : {n}자

사연 원문과 연락처는 메일에 담지 않습니다 — 관리 화면에서 확인해 주세요.
```

### 3-1. 🔴 설정이 필요합니다 (CEO)

메일 인프라가 프로젝트에 **없었습니다**. 의존성 없이 Resend REST 를 직접 부르도록 붙였고,
환경변수 셋을 넣으시면 그 순간부터 발송됩니다. **없어도 접수는 정상 저장됩니다**(경고 로그만 남음).

| 변수                | 값                                                          |
| ------------------- | ----------------------------------------------------------- |
| `RESEND_API_KEY`    | Resend 대시보드의 API 키                                    |
| `STORY_INBOX_EMAIL` | 사연 알림을 받을 청담해화당 주소                            |
| `STORY_MAIL_FROM`   | 발신 주소(도메인 인증 필요, 예: `webtoon@k-haehwadang.com`) |

## 4. 댓글 시스템

- 회차마다 · 로그인 사용자 · **표시는 공개 이름 하나뿐**(user_id 는 화면으로 내려보내지 않는다).
- 길이 1~500자 · 한 회차당 20개 · 분당 10회(rate limit).
- **소프트 삭제** — 행을 지우면 "지워진 자리"가 사라져 대화가 앞뒤 없이 붙어 읽힌다.
- 금칙어 필터는 두지 않았다. 낱말 목록은 반드시 새고, 새는 순간 정상적인 말이 막힌다 —
  신고·가림은 운영의 일이지 도메인의 일이 아니다. (신고 기능은 §5 결정 대기)
- 댓글 INSERT 는 **사용자 클라이언트**로 한다(admin 이 아니다) — RLS 가 최종 관문이어야 하므로.

---

## 5. 결정 대기 (CEO)

1. **메일 환경변수 3종** (§3-1) — 넣으시면 즉시 발송 시작.
2. **사연 선정 보상** — 이용권 / 복채 / 원화 / 크레딧 표기. 정해지면 폼에 명시.
3. **댓글 신고 기능** — 지금은 없다. 연재 시작 전에 넣을지.
4. **회차 등록 경로** — 지금은 DB 직접 입력이다. 어드민 화면이 필요하면 별건.
