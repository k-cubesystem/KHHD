## 0. 결론 먼저 (아침 3분 요약)

**"기획대로 가고 있는가" — 예. 코드 기반은 건강하다(A1 P0 0건).** 그러나 게이트(테스트 1,275개
전부 초록)가 **구조적으로 못 잡는 무증상 사망 3계열**이 실브라우저·라이브 DB 감사에서 나왔고,
전부 야간에 수복했다:

1. **보안 P0 3건** (A3) — 유료 신위·테마 무료 착용 뒷문 / 무료 상한 동시요청 우회 / 소원 사칭
   삽입. → 코드 수복 + 마이그레이션 2건, 전부 라이브 적용·검증 완료.
2. **기능 P0 2건** (A2, 프로덕션 실측 재현) — 오방기 전용 페이지 **영구 교착**(연출 CSS 미적재
   라우트에서 animationend 가 영원히 안 옴) / 액막이 진행 버튼이 가이드 바에 **차단**(z 역전).
   → 야간 수복·배포.
3. **디자인의 실체적 원인** (A4) — "형식적"의 물리 원인 중 하나가 **골드 위계 37곳의 무증상
   미렌더**(tailwind 슬롯 부재로 클래스 미생성)였다. → 소생 + 의식 독 통합 등 P1 집행.

프로덕션 보안 헤더 실측 정상(HSTS·CSP 등 6종) — 7/11부터 남아 있던 검증 항목 해소.

## 2. A1 기획 정합 — 결과 확정분

**총평: 기획대로 가고 있다.** 게임필 부록 A~E 확정 사항 거의 전량 이행(자유 팬·폭 320·입장 걸음
파생·9국면 회전·접지 계약·좌석 전구역·reduced-motion). 의식 3종은 프라이버시 약속(원문 무저장)이
스키마 강제 + 액션 시그니처 + 테스트의 3중으로 **기획보다 강하게** 들어갔고, 과금은 "무료 우선 →
명시 동의 → 실패 환불" 순서라 구조적으로 사고가 안 난다. 마이그레이션 6건 전부 라이브 적용 확인.

**기능 격차 P1 3건**
| # | 격차 | 판단 |
| --- | --- | --- |
| G1 | 합동 기도 **가족 기원 보너스(+1)** 미구현 — 만개 연출만 있음 (PRD 안3) | 재화 지급 로직 — 야간 자율 범위 밖(지급 정책은 CEO 확인 후) |
| G2 | 축원 영상 파이프라인 미착수(자리만) | 첫 완주자까지 ~100일 여유 — 별도 차수, 아침 결정 |
| G3 | 오방기 신당지기 연출이 전용 페이지 이관 때 기록 없이 소멸 | 페이지에서의 대체 연출을 A4 디자인안과 함께 판단 |

**의도적 표류(전부 코드 주석에 사유 있음 — 정당)**: wish_text 폐기(실물 굿 보류의 귀결) ·
완주 자동 확정 → 수동 갈무리(연출 없는 트로피 방지) · 트로피 3등급·백일 소원끈 신설(유익 방향).

**문서 부채 8건(P2)**: PRD 부록 F 부재(6차 검수 11건 — 세로선 진범=문틀 그림자 포함) ·
ARCH 모듈명 불일치 4건 · 로드맵 v2에 의식 트랙 부재 · MEMORY의 "마이그레이션 미적용" 낡은 기록 등.

## 4. A3 보안 — 신규 11건 (P0 3 / P1 3 / P2 5) + 기존 잔여 4건

**오늘 배포분의 DB 층은 통과.** 신규 RPC 5종 전부 service_role 전용 + search_path 고정(어드바이저
신규 지적 0), 신규 테이블 3종 RLS 정상. 설계가 막겠다고 선언한 것(이중지급·과금 순서·원문 유출·
프로토타입 오염)은 전부 실제로 막혀 있음이 라이브 대조로 확인됐다.

**P0 — 오늘 밤 수복 (실제 악용 경로)**
| # | 결함 | 악용 | 수복 방향 |
| --- | --- | --- | --- |
| S-P0-1 | `shrines_update_own` 이 **컬럼 제한 없는 UPDATE** 를 열어 둠. 서버는 `owned` 를 계산하고도 안 씀 | `PATCH /rest/v1/shrines {main_deity_id, active_pack_id}` 한 방으로 유료 신위(39,900원)·유료 테마(19,900원) 무료 착용 | ①신위·테마 착용 액션을 소유권 검증 + admin 경유로 ②배포·회귀 ③컬럼 권한 축소(GRANT UPDATE 컬럼 화이트리스트) — 순서 고정(S1b 교훈) |
| S-P0-2 | 오방기·액막이 RPC가 **잠금 없는 count-then-insert** | 50 병렬 요청 → 무료 50회(회당 1만냥 회피) | RPC에 `pg_advisory_xact_lock` 1줄 (CREATE OR REPLACE) |
| S-P0-3 | `wishes_insert_any`(WITH CHECK true) — 오늘 배포한 좌석 presence가 `is_owner_wish` 를 소비하며 영향 확대 | 남의(비공개 포함) 신당에 anon 으로 소원 삽입·좌석 점등 조작 | WITH CHECK 강화(is_owner_wish 는 소유자만·비공개 신당 차단). 기존 방문 소원 기능은 보존 |

**P1 — 오늘 밤 수복 2건 + 문서화 1건**

- 의식 액션 4종 **멤버십 게이트 부재**(페이지는 layout 이 막지만 액션은 공개 엔드포인트 — 같은 커밋의
  family-hall.ts 는 걸어 뒀음) → 동일 게이트 이식.
- 의식 액션 **rate limit 부재**(상한 RPC는 거절 호출을 안 셈) → 기존 check_rate_limit 연결.
- 오방기 **시드 역산 = 실제 가능(YES)**. 단 색에 재화가 안 걸려 있어 경제 피해 0 —
  "색 기반 보상 추가 시 서버 판정 전환 필수"를 코드 주석 + 본 문서에 못박고 야간 리팩터는 하지 않음.

**기존 잔여**: R1·R2·R4·R5 라이브 해소 확인 / R7(`admin ?? supabase` 폴백)은 S1b 이후 위험도 상승
(조용한 실패) → 야간에 폴백 제거 / R6·R10 잔여는 Track S 로.

## 5. A4 디자인 품질 상향 — "형식적"의 물리적 원인 5가지 + 처방

**핵심 발견: 골드 위계가 실제로 죽어 있었다.** `text-gold-200`(신당 37곳 — 스트립 이름표·의식
시트 제목·CTA·가이드바)이 tailwind 설정에 **없는 슬롯**이라 클래스가 아예 생성되지 않았다
(빌드 청크 grep 0건 실측, 대조군 gold-300 은 정상). 골드 라벨이 전부 흰 상속색으로 렌더되고
있었다 — CEO가 반복해서 느낀 "형식적"의 실체적 원인 중 하나. styled-jsx 사건과 같은
**무증상 사망** 계열이다.

| #    | 원인                                       | 처방                                                                 |
| ---- | ------------------------------------------ | -------------------------------------------------------------------- |
| P1-0 | 죽은 클래스(gold-200·gold-dim·white/8)     | 슬롯 등록 + 치환 + **빌드 CSS grep 게이트** — ✅ 야간 집행 완료      |
| P1-1 | 동형 스트립 5곳 반복(목록처럼 읽힘)        | **의식 독(儀式 dock)** — 카드 하나 + 신당 최초의 단청 리듬 + 44px 행 |
| P1-2 | 도장 CTA 규약(3px) 실종 — 신기능 전부 12px | 버튼 반경 3단 문법(주=도장 3px / 보조=8px / 칩=full)                 |
| P1-3 | 팻말 각자 품질                             | 금박 그라디언트 + 홈 그림자 + 900 (실물 널 렌더로 B안 검증)          |

## 6. 야간 실행 원칙 (자율 범위의 경계)

1. **AI 이미지 생성 금지** — 17신위 확산(≈$2)·G-4 테마 확산은 "시범 검수 후 양산" 게이트 유지.
   앰비언트 5회 반려의 교훈. 아침 GO 대기.
2. **재화·지급 정책 신설 금지** — 합동 기도 보너스 같은 지급 로직은 금액·정책이 기획 결정.
3. **마이그레이션은 추가 전용만**, 적용 전 라이브 스키마 대조.
4. **CEO 검수 통과 요소 불가침** — 연소 연출·오방기 실물 형태·신위 회전·무라 퀼팅.
5. 배포는 통합 게이트(tsc·jest·build·check-animation-css) 전량 통과 후.
