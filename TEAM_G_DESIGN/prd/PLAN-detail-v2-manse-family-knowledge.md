## S1. 사주풀이 영상 연출 (발주 ①)

**실측**: 사주 결과의 실제 로더는 `SajuLoadingContent`(saju-result-client.tsx:1137, 인라인·프로그레스+7단계+상식카드). `SajuLoadingOverlay`·`CheonjiinLoadingState`는 **오펀**이라 거기 연결된 `analysis-ambient` 영상(세션27 생성, 786KB)이 **어디서도 재생 안 됨**. 결과 화면의 명확한 챕터 경계는 天(saju-result-client.tsx:274)·天→地 전환(688~691) 2곳(人 전용 섹션은 없음 — 天 하위 흡수).

**결정 — 유휴 영상을 2곳에 배선(신규 영상 생성 없음, $0)**:

- **S1-a 로딩 중 앰비언트**: `SajuLoadingContent` 배경(프로그레스바 뒤 레이어)에 `<AmbientVideo id="analysis-ambient" className=은은한 흐린 배경 fallback={null}>` 삽입. 기존 프로그레스·상식카드는 그 위(z-index)에 유지 — 로더를 갈아엎지 않고 배경만 추가. reduced-motion·파일부재 시 자동 폴백(현행 AmbientVideo 계약).
- **S1-b 天→地 전환 구분자**: 결과 스크롤 天 섹션 끝(≈688) ↔ 地 섹션(≈691) 사이에 얇은 시네마틱 디바이더(높이 ~120px, `analysis-ambient` 루프 + "地 · 삶의 터전" 캡션 오버레이). 몰입 챕터 전환. 영상 없으면 기존 단청 디바이더로 폴백.
- **S1-c 결과 공개 순간**: 현재 chime 1회만 — 로딩→결과 하드 스왑(800ms)을 framer-motion 크로스페이드(opacity 0→1, 0.5s)로 부드럽게. sparkle 파티클 1회는 과하면 생략(성능 우선).
- 오펀 정리: `SajuLoadingOverlay`·`CheonjiinLoadingState`는 이번에 실사용처가 생기지 않으면(위는 SajuLoadingContent 직접 수정) 삭제 후보로 보고만 — 임의 삭제 금지(세션28에서 '合 로더' 보류 맥락 존중).
- 검증: saju-result 로딩·결과 e2e 에서 `<video>` 존재 또는 폴백 무크래시 + console 0.

## S2. 내 명식 보기 개편 (발주 ②)

**실측**: `manse-client.tsx` **2827줄 단일 클라 컴포넌트**, 13개 분석엔진을 **비메모 동기 실행**(다이얼로그 클릭·대상 전환마다 전체 재계산 → 느림). 3탭(나의사주/운세흐름/분석리포트)인데 **운세흐름 탭이 8섹션+위험블록6종 과적재**. 두 엔진(`saju-engine` vs `manse-advanced`)이 같은 개념을 병렬 렌더 → **9종 중복**(신살 3회, 공망 3회, 용신 활용정보 4회 등). 설명은 `SECTION_DESCRIPTIONS`에 있으나 신살·대운·십이운성·십성 등에서 **정의만 하고 렌더 안 함**. 지장간은 아예 미표시.

**결정 — "3탭 유지, 내용 정리 + 설명 보강 + 성능"**(탭 구조 재설계는 리스크 커 범위 밖; 사용자 불만의 실체는 "중복·설명부족"이므로 그것을 정면 해결):

**S2-a 중복 제거(9종)** — 각 개념을 **한 곳(정본)만** 남기고 나머지 렌더 제거:
| 개념 | 정본(유지) | 제거 |
|---|---|---|
| 신살 | mysaju 탭 1곳 | 운세흐름 재노출 + report(AdvancedManseDisplay) 중복 |
| 십이운성 | 운세흐름 1곳 | report 중복 |
| 합충형 | 운세흐름 1곳 | report 중복 |
| 공망 | 운세흐름 관계 블록 | warnings 재노출 + report 중복 |
| 세운 | 운세흐름 대운·세운 | report 중복 |
| 신강신약/십성 | report 1곳 | 물상론 내 재노출 |
| 용신 활용정보(색/방위/직업) | 용신론 1곳 | 개운법 재노출(개운법은 '행동'만) |
| 물상론 | 운세흐름 1곳 | 종합 dialog 요약 제거 |
| 종합풀이 dialog | 유지하되 탭 본문과 겹치는 요약 축소(dialog는 "링크 요약"이 아니라 "종합 서사"로 역할 분리) |

- report 탭의 `AdvancedManseDisplay`가 중복의 주범 → report 탭은 "고급(원본 데이터 표)"에서 **신강신약·십성분포 + 지장간(신규)** 중심으로 슬림화. 중복 렌더 제거로 줄 수·재계산도 감소.

**S2-b 설명 보강**: 렌더 안 되던 `SECTION_DESCRIPTIONS`(신살·대운·십이운성) 인라인 노출 + 신강신약·십성·육친·오행분포에 한 줄 해설(소스는 `lib/constants/saju-terms.ts` TERMINOLOGY 재사용 — S4 지식 공용화와 합류). **지장간 섹션 신규**(각 지지의 지장간 + "지지 속에 숨은 천간의 기운" 한 줄 설명).

**S2-c 성능**: 13개 엔진 호출을 `useMemo`(deps: 대상 saju 입력)로 감싸 다이얼로그 클릭 시 재계산 제거. 죽은 코드 삭제: `SINSAL_ADVICE`·`GONGMANG_SOLUTION`·미사용 `SECTION_DESCRIPTIONS` 4개·미렌더 `sinsalList` 계산.

**S2-d 용어 툴팁**: 전문용어에 밑줄+탭 시 툴팁(S4 지식 사전과 동일 소스). 최초 진입 mysaju 탭은 그대로(팔자표 먼저).

- 검증: 렌더 텍스트에서 각 중복 개념이 1회만 나오는 스냅샷/카운트 + 만세 페이지 e2e 렌더·console 0. **본인 사주 계산 결과 불변**(리팩터링이므로 값 회귀 없어야 — 골든 대상 있으면 대조).

## S3. 가족 관리 (발주 ③, 4소항목)

**S3-a 본인 레코드 숨김** — 실측: 등록 폼엔 '본인' 옵션 없음. `saveSelfFamilyMember`(profile.ts:70)·`getSelfFamilyMemberId`(fortune.ts:336)가 사주 계산용으로 `relationship='본인'` 행을 자동 생성. 목록(`getFamilyWithMissions`)이 이를 안 걸러 카드로 뜸. **본인 행에 의존하는 소비처는 전부 DB 직접 조회 → 표시에서 숨겨도 안전. 행 삭제는 금지**(재생성 의존).

- 결정: 목록 렌더에서 `relationship !== '본인'` 필터 — 위치는 `getFamilyWithMissions` 결과 소비처(`family/page.tsx` 또는 client map 직전). **일관성 동반 수정**: ①관계 한도 count(`membership.ts:94`)에서 본인 제외(무료 3명이 실질 2명 되던 것 정정) ②기운지도 member 쿼리(`energy-map.ts:86`)에서 본인 family행 제외(profiles self 와 이중 계상 방지). ⚠️ `membership.ts`·`family.ts`는 **타 세션 보호 파일** — count 필터를 그 파일에서 못 고치면 **그 항목만 보류·기록**하고 목록 숨김·기운지도는 진행.

**S3-b "연인관리"→가족** — 실측: 코드엔 "연인 관리" 문구가 **없고** 프로필 라벨은 이미 "인연 관리"(`profile/page.tsx:413`). → 사용자 오독. **결정**: 라벨을 **"가족·인연 관리"**로 명확화(가족이 주임을 드러냄). href·기능 불변. 등록 폼 관계 옵션의 '연인'은 유지(실제 관계 유형).

**S3-c 신위 아바타 선택** — 실측: 렌더 3곳(카드·기운지도·신당탭)이 모두 `findFiveAvatar` 하나로 수렴. `avatar_id`는 임의 문자열 저장이라 스키마 변경 불필요. 신위 17종 `portrait.webp` 존재.

- 결정: `lib/domain/family/avatars.ts` 신설 — 오행 정령 5종 + 신위 17종을 한 카탈로그로 통합(`{id, label, src, kind:'element'|'deity', element}`). `findFiveAvatar`를 이 카탈로그 조회로 확장(기존 5종 id 불변 → 기존 데이터 호환). 선택 UI(`FiveAvatarSelector`)에 "오행 정령 / 신위" 2구획 그리드. `FiveAvatar.element` 5-union은 신위에 대표 오행 부여 또는 optional 처리.
- 검증: 기존 avatar_id 렌더 불변 + 신위 id 저장·렌더 단위 테스트. (프로필 아바타는 경로형이라 이번 범위 밖 — 가족만.)

**S3-d 기운지도 시인성 + 오행 설명** — 실측: 진입 카드 저채도(존재감 약), 지도 화면에 **오행이 뭔지 설명 전무**(한자+수치·용신 문장만). 오행 설명은 `lib/data/saju-knowledge-graph.ts:43-83`에 이미 있음(木='나무·봄·동쪽·생장'/'仁의 덕목').

- 결정: ①진입 카드 채도↑(gold 테두리 강화 + "N명의 기운을 한눈에" 요약 수치 노출로 클릭 유인) ②지도 화면에 **「오행이란?」 접이식 설명 섹션** — 5행 각각 아이콘·색·한 줄 의미(생장/확산/중재/결실/응축)·예시(木=나무처럼 뻗는 성장·仁). saju-knowledge-graph 재사용 + S4 공용 데이터와 합류. ③각 구성원 막대에 최강/최약 색 강조는 유지, 막대 위 오행명 한글 병기(木→"목").

## S4. 하단 가이드 — 사주·풍수 지식 팁 (발주 ④)

**실측**: `GlobalGuide.tsx` 우선순위(개인알림>공지>온보딩>투어), 투어 정의된 페이지만 접힌 바 유지·나머지는 바 소멸. 지식 조각은 이미 풍부: `saju-terms.ts` TERMINOLOGY(십성10·신살15·십이운성12·용신·합충형), `saju-knowledge-graph.ts`(오행5 description+detail), `compatibility-result.tsx` CATEGORY_DEFINITIONS(8대 궁합 평문). GlobalGuide 단일 파일 수정으로 끼워넣기 가능.

**결정 — 지식 팁을 가이드의 최하위 콘텐츠로 상시화**:

- `lib/domain/guide/knowledge-tips.ts` 신설 — 위 소스에서 **평문 팁 풀** 구성(용어명 + 쉬운 한 줄 + 카테고리). 예: "오행(五行) — 세상 기운을 나무·불·흙·쇠·물 다섯으로 나눈 것이에요", "삼재(三災) — 12년에 한 번, 3년간 조심하는 시기예요", 풍수 기초(배산임수·문·현관 등 — 풍수 항목은 saju-terms에 없으면 신규 10개 내외 평문 작성, 근거 불명확한 술수적 단정은 피하고 통념 수준으로).
- GlobalGuide: Bubble 타입에 `'knowledge'` 추가 → `hasContent`에 포함(**모든 페이지에서 접힌 바 유지**, 지금은 투어 없는 페이지에서 바가 사라짐) → 자동노출 우선순위 최하위(개인알림·공지·온보딩·투어가 없을 때만) → **접힌 바 탭 시 팁 회전**(progress 소진형 아님, `(idx+1)%len` 회전 인덱스) → 렌더 블록에 knowledge 케이스("💡 오늘의 사주 상식" 헤더 + 팁 + "다른 상식 보기" 탭).
- 팁은 하루 1개 시드(날짜 기반 결정적 인덱스로 "오늘의 상식")로 자동 노출, 탭하면 회전. 신탁·공지·온보딩이 있으면 그것이 우선(지식은 조용한 기본값).
- 검증: knowledge-tips 풀 단위 테스트(전 항목 비어있지 않음·길이 상한) + GlobalGuide 렌더에 knowledge 케이스 노출 e2e(투어 없는 페이지에서 바 유지).
