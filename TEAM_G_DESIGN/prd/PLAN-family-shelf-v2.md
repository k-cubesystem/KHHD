### 1-3. 세로 정합 — 아이템은 «자기 널»이 아니라 «한 칸 아래 널» 위에 서 있다

`FSHELF_TIERS.boards = [0.31, 0.55, 0.76]` 를 스프라이트 실측 널 상면과 대조하면:

| 단  | 코드 널 (room %) | 스프라이트 실제 널 | 차             | 비고                      |
| --- | ---------------- | ------------------ | -------------- | ------------------------- |
| 1단 | 53.02            | **50.04**          | +2.98%p (18px) | 열린 칸 2의 한복판        |
| 2단 | 63.10            | **59.87**          | +3.23%p (20px) | 열린 칸 3의 한복판        |
| 3단 | 71.92            | **68.90**          | +3.02%p (19px) | **닫힌 수납장 문짝 안쪽** |

여기에 렌더 규약이 하나 더 겹친다. `transform: translate(-50%,-50%) scale(s)` +
`transform-origin: 50% 100%` 의 합성 결과, 아이템의 **그려진 밑변은 배율과 무관하게 저장 y +
(원치수 높이 ÷ 2) = y + 58px(9.35%p)** 다. 그런데 앵커는 `널 − itemLift(3.5%p)` 로 잡혀 있다.

```
1단  앵커 y 49.52 → 아이템 발 58.87  (실제 널 50.04 보다 8.84%p = 55px 아래)
2단  앵커 y 59.60 → 아이템 발 68.95  (실제 널 59.87 보다 9.09%p = 56px 아래)
3단  앵커 y 68.42 → 아이템 발 77.77  (수납장 상면 68.90 보다 8.88%p = 55px 아래)
```

1단 아이템의 발(58.87)은 **2단 널(59.87)에서 1%p 위**다. 즉 화면에서는 «자기 널»이 아니라
**한 칸 아래 널에 얹힌 것처럼** 보이고, 몸통은 위 널을 뚫고 33px 올라간다.
발이 널에 닿으려면 `itemLift = 3.5 → **9.35**`(= 아이템 반높이 파생)여야 한다.

### 1-4. 자석 폐지 이후 남은 잔해 — "칸"은 이미 존재하지 않는다

- **`fshelfSlotAnchors`(3×3 칸)는 프로덕션에서 한 번도 호출되지 않는다.** 룸이 부르지 않고,
  테스트가 «부르지 않음»을 계약으로 못 박고 있다(`ROOM not.toContain('fshelfSlotAnchors(...)')`).
  화면에도 칸 표시가 없다. 남아 있는 유일한 실동작은 **「상자 안이면 0.6배로 줄인다」** 뿐이다.

  왼벽이 x 1.475~39.525(38.05%p = **화면 1.22장**) 하나짜리 축소 구역이 된다.
  → 선반 «앞»·«사이»에 두려던 물건도 예고 없이 40% 작아진다. 경계는 화면에 안 보인다.
- 같은 널에 층이 다른 물건이 서면 배율이 갈린다:
  **벽 69.6px · 제단(틀 테마) 41.8px · 바닥 50~57px** → 한 줄에서 **1.67배** 차이.
  깊이 z도 층 고정(벽 11 · 제단 13~15 · 바닥 16~28)이라 «앞뒤»가 위치가 아니라 층으로 정해진다.

### A안 — 「가족 문패 줄」 (진열 폐지)

**개념**: 사방탁자를 걷고, 가족마다 아바타 + 이름의 **문패 한 장**만 벽 상부에 한 줄로 건다.

```
world x  0                    31.25(한 화면)
  y34   ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐
        │◍ │ │◍ │ │◍ │ │◍ │ │◍ │ │◍ │   문패 6장
        │이름│ │이름│ │이름│ │이름│ │이름│ │이름│   폭 4.2%p × 세로 6%p
  y40   └──┘ └──┘ └──┘ └──┘ └──┘ └──┘
        x 6   11.6  17.2  22.8  28.4  34     (총 3.9~36.1 = 32.2%p)
```

- **점유**: 6장 25.2%p × 세로 6%p → 벽 점유 86.2% → **57%**, 벽면 세로 48% → **9%**.
- **데이터**: 축소 규칙 소멸 → 상자 안 18건이 그 자리에서 **1.67배 커진다**(좌표 이동 0).
  `seat:fshelf:` 8건은 무의미한 표식으로 남는다(dangling 은 이미 정상 상태). **마이그레이션 0**.
- **렌더 변경**: `FamilyShelfWall.tsx`(전면 재작성) · `family-shelf.ts`(TIERS·anchors·itemScale 제거) ·
  테스트 2벌(`family-shelf.test` · `theme-stage.test` 의 선반 절).
- **장점**: 점유 문제를 가장 확실히 해소. 틀이 방의 주인공이 된다. 자산 0(현판 `plaque.webp` 재사용).

### B안 — 「반가 선반 v2 : 1가족 1진열」 ★ 추천

**개념**: 사방탁자를 **2단으로 줄이고 기둥을 슬림화**해서, 가족당 **한 점**을 제대로 진열한다.
아이템이 칸에 들어가는 크기가 되는 것이 요점 — 칸을 줄이는 게 아니라 **프레임 낭비를 걷는다**.

```
현행 유닛 8.65 × 42            →      B안 유닛 6.8 × 28
 y40 ┌──────────┐ 천판                y54 ┌────────┐ 천판
     │ ◍ 66px 원반 │ 칸 41px(160%)         │ ◍ 50px  │  칸에 맞는 아바타
     │  [이름패]   │                       │ [이름패] │
     ├──────────┤ 실제 널 50.04         ├────────┤ ── 널 (계약의 유일한 줄)
     │  ▣▣▣ 겹침 40~56% │ 칸 48px               │   ▣    │  개구 80px · 아이템 69.6px (87%)
     ├──────────┤ 실제 널 59.87         │        │
     │  ▣▣▣     │ 칸 44px               └┘    └┘ 접지선 82
     ├──────────┤ 수납장 상면 68.90
     │ ▤▤ 닫힌 수납장 │ ← boards[2]=0.76 이 문짝 한가운데
 y82 └┘      └┘ 접지선 82
```

**규격 (전부 파생식으로 못 박는다)**

| 항목           | 현행                          | B안                                      | 근거                                                              |
| -------------- | ----------------------------- | ---------------------------------------- | ----------------------------------------------------------------- |

### C안 — 「좌석·진열 분리」

**개념**: 가족은 **문패 줄**(A안), 진열은 **제단 좌우 공용 진설대 2좌**로 몰아 넣는다.

- **공수**: 2일.

## 4. 부록 — 이번 진단에서 함께 드러난 이웃 결함 (별건, 이번 범위 밖)

- **의식각(RitualHall) 현판 자리도 같은 방향으로 어긋나 있다.** 같은 스프라이트를 쓰는데
  `PLAQUE_CY = [0.155, 0.425, 0.65, 0.865]` 를 실측 칸 중심(0.158 / 0.378 / 0.599 / 0.808)과
  대조하면 2~4번째가 일관되게 **0.047~0.057 아래**다(현판이 칸 아래턱을 물고 있다).
  선반 v2 의 «실측 정본» 표를 만들 때 **같은 표를 공유**하면 한 번에 정리된다.
- **`shelf-sabang.webp` 는 `objectFit: 'fill'`** 이라 기준 방(520)에서 사방탁자가 가로로 **30% 뚱뚱**하다
  (스프라이트 종횡비 0.423 vs 상자 0.553). 폰에서는 거의 맞는다 — 즉 데스크톱에서만 비례가 깨진다.
  B안에서 상자 종횡비를 스프라이트에 맞춰 잡으면 함께 해소된다.
