## 0. 한 줄 정의

**"내 사주·관상·손금이 만드는, 살아있는 나만의 신당."**
분석 데이터(命)가 신당의 기운을 결정하고, 아이템(物)으로 부족한 기운을 채우고, AI 신당지기(靈)와 언제든 대화한다.

## 1. 왜 만드는가

| 현재 문제                                        | 신당 2.0의 답                                                    |
| ------------------------------------------------ | ---------------------------------------------------------------- |
| 분석(사주/관상/손금)이 **일회성 소비** — 보고 끝 | 분석 결과가 신당의 **영구 상태**가 됨 (기운 프로필)              |
| 신당 1.0은 **장식일 뿐** — 아이템에 의미 없음    | 아이템 = **오행 기운 장착** — 내 용신(필요 기운)을 채우는 목적성 |
| AI 채팅이 기능 페이지에 숨어 있음                | 신당 = **홈** — 들어오면 신당지기가 먼저 말을 건다               |
| 리텐션 루프 부재                                 | 매일: 기운 상태 확인 → 문안 인사 → 아이템/부적 → 대화            |
| 수익화가 분석 단건 결제뿐                        | 테마 팩 + 아이템 + 시즌 한정 = **게임형 수익 모델**              |

**타깃 정서**: 궁금증(운세)과 **외로움**(동반자). 40-50대 주 고객이 매일 들르는 "마음의 사랑방".

## 2. 핵심 시스템 ① — 기운(氣運) 엔진: 세 분석의 융합점

신당 2.0의 심장. 사주+관상+손금이 하나의 **오행 기운 프로필**로 수렴한다.

### 2.1 기운 프로필 (user_energy_profile)

```
사주 엔진 (이미 존재)          관상 분석          손금 분석
 ├ 오행 분포 (木火土金水)       ├ 오행 보정치       ├ 오행 보정치
 ├ 용신(用神) = 필요 기운       └ 관상 키워드       └ 손금 키워드
 └ 기신(忌神) = 과한 기운
        ↓ 가중 합산 (사주 60% / 관상 25% / 손금 15%)
┌─────────────────────────────┐
│  오행 게이지: 木▓▓░ 火▓░░ 土▓▓▓ 金░░░ 水▓░░  │
│  필요 기운: 金 (용신) → "금 기운 아이템 추천"  │
└─────────────────────────────┘
```

- **DB**: `user_energy_profile` (user_id PK, element_wood/fire/earth/metal/water INT 0~100, yongsin_element, gisin_element, face_modifier JSONB, palm_modifier JSONB, computed_at)
- 사주 엔진의 `elementsDistribution` + `advancedYongsin`은 이미 계산됨 → 저장만 추가
- 관상/손금 분석 시 오행 보정치를 결과 JSON에 포함하도록 프롬프트 확장 (§5 참조)
- 분석을 안 한 사용자: 사주만으로 프로필 생성, 관상/손금 슬롯은 "?"로 표시 → **분석 업셀 동선**

### 2.2 아이템 = 기운 장착

`shrine_item_catalog` 확장:

```sql
ALTER TABLE shrine_item_catalog ADD COLUMN element TEXT CHECK (element IN ('wood','fire','earth','metal','water') OR element IS NULL);
ALTER TABLE shrine_item_catalog ADD COLUMN energy_power INT DEFAULT 10;   -- 기운 충전량
ALTER TABLE shrine_item_catalog ADD COLUMN pack_id UUID REFERENCES shrine_theme_packs(id); -- 테마 소속(선택)
ALTER TABLE shrine_item_catalog ADD COLUMN placement_layer TEXT NOT NULL DEFAULT 'floor'
  CHECK (placement_layer IN ('wall','hanging','altar','floor'));          -- 배치 가능 구역 (§3)
ALTER TABLE shrine_item_catalog ADD COLUMN sprite_url TEXT;               -- 스프라이트 에셋
ALTER TABLE shrine_item_catalog ADD COLUMN size_grade TEXT DEFAULT 'md' CHECK (size_grade IN ('sm','md','lg'));
```

- 아이템마다 오행 속성: 청죽(木), 홍촉(火), 옹기(土), 풍경(金), 수반(水)…
- **장착 효과**: 신당의 총 기운 = 기본 프로필 + Σ(방에 놓인 아이템 energy_power)
- **추천 로직**: 용신이 金인 유저에게 상점 최상단에 金 아이템 + "당신에게 필요한 기운" 배지
- 기운 충족 시 신당 비주얼 변화: 오행 밸런스 달성 → 신당 글로우 강화, 파티클 증가 (선명한 보상감)

### 2.3 데일리 루프 (리텐션)

```
접속 → 신당 진입(홈) → 신당지기 문안 "오늘 화 기운이 강한 날이오..." (오늘 일진 × 내 프로필)
  → 오늘의 기운 게이지 확인 → [기원하기 +10복] → 아이템/부적 확인 → 대화 or 이탈
```

- 문안 인사: 서버 액션에서 일진+프로필 기반 1문장 생성 (FLASH, 일 1회 캐시)
- 기존 출석체크/복 미션과 통합: 신당 방문 = 출석

## 3. 핵심 시스템 ② — 미니룸 꾸미기 (싸이월드 계승)

**신당은 슬롯 그리드가 아니라 "방"이다.** 싸이월드 미니룸처럼 벽·바닥·제단이 있는 공간에 아이템을 **자유 좌표로 끌어다 놓고** 배치·이동·수납하며 관리한다.

### 3.1 공간 구조 — 4개 배치 레이어

```
┌────────────────────────────┐
│  hanging  풍경·등롱 (천장)     │  ← 위에서 매달림
│  wall     족자·부적·현판 (벽)  │
│  ┌──────────────┐          │
│  │ altar 제단 위  │ 촛불·향로·공물 │  ← 제단 상판
│  └──────────────┘          │
│  floor    방석·항아리·화분 (바닥)│  ← y좌표로 자동 앞뒤 정렬
└────────────────────────────┘
```

- 렌더링: **2D 레이어드 씬** (배경 이미지 + 절대좌표 스프라이트). 아이소메트릭 엔진 불필요 — 싸이월드 미니룸도 평면 2D + 겹침 순서였음. floor 레이어는 y좌표가 클수록 z-index 상승(앞에 있는 물건이 가림)
- 아이템은 `placement_layer`가 허용하는 구역에만 배치 가능 (벽걸이를 바닥에 못 놓음 — 시각적 파탄 방지)
- 배치 상한: 기본 20개, 신당 레벨/멤버십으로 확장

### 3.2 소유와 배치의 분리 (인벤토리)

현재 1.0은 "구매 = 즉시 슬롯 배치"라 보관 개념이 없음. 2.0은 게임 표준으로 분리:

```sql
-- 소유 원장 (같은 아이템 여러 개 가능 — 촛불 4개 등)
CREATE TABLE user_shrine_inventory (
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  catalog_item_id UUID REFERENCES shrine_item_catalog(id),
  qty INT NOT NULL DEFAULT 1 CHECK (qty >= 0),
  PRIMARY KEY (user_id, catalog_item_id)
);

-- 배치 (기존 shrine_items의 slot_index 대체)
CREATE TABLE shrine_placements (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  shrine_id UUID REFERENCES shrines(id) ON DELETE CASCADE NOT NULL,
  catalog_item_id UUID REFERENCES shrine_item_catalog(id) NOT NULL,
  layer TEXT NOT NULL CHECK (layer IN ('wall','hanging','altar','floor')),
  x NUMERIC(5,2) NOT NULL,   -- 무대 가로 % (0~100)
  y NUMERIC(5,2) NOT NULL,   -- 무대 세로 % (레이어 존 내부로 클램프)
  flip BOOLEAN DEFAULT FALSE,
  placed_at TIMESTAMPTZ DEFAULT now()
);
```

- 마이그레이션: 기존 `shrine_items.slot_index` → 기본 좌표 테이블로 1회 변환 후 뷰 유지
- 저장 전략: 꾸미기 모드에서 로컬 상태로 자유 편집 → **[저장]** 시 placements 일괄 upsert (Optimistic UI, 실패 시 롤백)

### 3.3 꾸미기 모드 UX

| 동작      | 인터랙션                                                                                                |
| --------- | ------------------------------------------------------------------------------------------------------- |
| 진입      | 신당 우상단 **[꾸미기]** 버튼 → 편집 모드 (배치 존 점선 표시)                                           |
| 배치      | 하단 **인벤토리 트레이**에서 아이템 탭 → 씬에 나타남 → 드래그로 위치 조정 (존 자동 클램프 + 8px 스냅)   |
| 이동/제거 | 배치된 아이템 탭 = 선택(핸들 표시) → 드래그 이동, [↔ 뒤집기], [수납] 버튼                               |
| 저장      | 상단 [저장] → 일괄 반영 + 신당지기 코멘트 1문장 ("서쪽에 풍경을 거니 금 기운이 살아나는구려")           |
| 방문자    | 보기 모드만 노출. 방명록(기존 shrine_wishes) + TODAY 방문자 카운터(싸이월드 감성, visitor_count 재활용) |

- 터치 최적화: 드래그 시작은 선택된 아이템만(오스크롤 오동작 방지), 롱프레스 불필요
- 에셋: MVP는 큐레이션된 스프라이트 20종 (SVG/WebP, 레이어별 5종). 이모지는 프로토타입 전용 — 실서비스는 일러스트 에셋 필수
- (확장) 테마별 국악 앰비언트 BGM 토글 — 싸이월드 BGM 감성

## 3b. 테마 패키지팩 (수익 축)

### 3b.1 구조

**테마 팩 = 방의 스킨 전체 교체** (벽지·바닥재·제단 스킨 + 파티클 + 컬러 액센트 + 전용 아이템 3종) — 싸이월드 미니룸 배경 팩과 동일한 문법.

```sql
CREATE TABLE shrine_theme_packs (
  id UUID PK, code TEXT UNIQUE,           -- 'hanok_night', 'dragon_palace'...
  name TEXT, description TEXT,
  price_bok INT DEFAULT 0,                -- 0 = 무료
  price_krw INT DEFAULT 0,                -- 원화 직접 구매가 (게임식)
  element_affinity TEXT,                  -- 테마의 오행 친화 (보너스 +5)
  season TEXT,                            -- 시즌 한정 (suneung/seollal/chuseok)
  assets JSONB,                           -- {wall, floor, altar_skin, particle, accent_color}
  is_active BOOL, sort_order INT
);
CREATE TABLE user_theme_packs (user_id, pack_id, acquired_at, PK(user_id, pack_id));
ALTER TABLE shrines ADD COLUMN active_pack_id UUID REFERENCES shrine_theme_packs(id);
```

### 3b.2 런칭 라인업 (6종)

| 팩            | 가격                 | 오행 친화 | 컨셉                                      |
| ------------- | -------------------- | --------- | ----------------------------------------- |
| **초가 신당** | 무료 (기본)          | —         | 소박한 초가집, 기본 팔레트                |
| **달빛 산사** | 무료 (7일 출석 보상) | 水        | 달빛+안개, 차분한 청색 액센트             |
| **조선 반가** | 5,900원 / 5만복      | 木        | DESIGN.md 무드 그대로 — 반가 서재, 단청   |
| **용궁**      | 9,900원              | 水        | 심해 청록+진주 파티클                     |
| **도깨비 불** | 9,900원              | 火        | 밤 숲+도깨비불 파티클                     |
| **황금 만당** | 19,900원 (프리미엄)  | 金        | 금박 만다라, 최대 글로우, 전용 아이템 3종 |

- **시즌 한정** (수능/설/추석): 기간 한정 판매 → 희소성. 구매한 팩은 영구 소장
- 팩 구매 = 전용 아이템 3종 동봉 (번들 가치 체감)
- 구현: `assets` JSONB만 읽어 렌더링하는 **테마 렌더러 1개** — 팩 추가는 DB INSERT + 에셋 업로드만 (코드 변경 0)

### 3b.3 비주얼 스타일 가이드 (디자인 초안)

DESIGN.md 시스템 위에 신당 전용 레이어:

- **레이아웃**: 480px 모바일. 상단 55% = **미니룸 씬**(벽 60% + 바닥 40% 원근, 중앙 제단), 중단 = 기운 게이지 바(오방색 5색), 하단 = 신당지기 대화 진입 + 방명록/TODAY 카운터
- **오방색 기운 게이지**: 木 `#4A7C59` 火 `seal(#9E2B2B)` 土 `#D4A017` 金 `gold-500` 水 `#2D5F8A` — 기존 obangsaek 토큰 활용
- **배치 존 힌트**: 꾸미기 모드에서 존 점선 표시. 용신 기운이 빈 존은 골드 점선 강조("金 기운 자리가 비어 있소")
- **아이템 그라운딩**: 스프라이트마다 타원 그림자(floor/altar) 또는 걸이 끈(hanging) — 공중부양 느낌 방지
- **모션**: motion-tokens 사용. 아이템 배치 시 `fadeInUp`+글로우 펄스, 기운 충족 시 파티클 버스트(1회, 700ms). 드래그 중 대상만 `scale(1.06)`+그림자 확대
- **신당지기 아바타**: 방 안에 상주하는 미니미 — 제단 옆에 서서 말풍선으로 문안. 팩 액센트 컬러로 오라 변경

## 4. 핵심 시스템 ③ — AI 신당지기 (상시 동반자)

### 4.1 통합 원칙

현재 **무당 채팅(shaman-chat)과 신당 채팅(shrine-chat)이 분리** → **신당지기 하나로 통합**한다.

- 신당 = 대화의 집. `/protected/shrine`이 홈 탭이 되고 채팅이 신당 안에 상주
- 백엔드: shaman-chat의 파이프라인(사주 컨텍스트 캐시 + user_ai_memory + 세션 요약 — **이미 구현됨**)을 그대로 사용하고, 신당 상태(테마/아이템/기운 게이지)를 컨텍스트에 추가
- shrine-chat.ts는 shaman-chat 호출로 리다이렉트 후 제거 (코드 중복 해소)

### 4.2 신당지기 컨텍스트 (프롬프트에 주입)

```
[신당 상태] 테마: 조선 반가(木) | 기운: 木72 火45 土60 金23 水51 | 용신: 金(부족)
[장착 아이템] 풍경(金+15), 복 부적(土+10), 황금 등불(金+20)
[기억] (이미 구현된 user_ai_memory top-5)
```

→ "풍경 소리가 금 기운을 불러오고 있소. 허나 아직 부족하니…" 같은 **신당 상태를 아는 대화** 가능

### 4.3 외로움 케어 (동반자 기능)

- **문안 인사**: 신당 진입 시 1문장 (일 1회 생성, 캐시)
- **아이템 반응**: 새 아이템 배치 직후 신당지기 코멘트 1문장 (배치 API 응답에 포함)
- **회귀 인사**: 7일+ 미접속 후 방문 시 "오랜만이구려. 그간 마음 쓰이던 이직 일은…" (memory 활용)
- 톤: §5의 통합 페르소나 규정을 따름. **의존 유도 금지** — 하루 대화 상한(질문권)은 유지

### 5.1 페르소나 통일 — "해화지기 화법 3단계"

**문제 (감사로 확정)**: 마스터 프롬프트(무속체 "~이외다"+시적 의무+번호 금지)가 모든 하위 유형과 충돌하며, **한 요청 안에 상호 배타적 말투 규칙이 2~3개 동시 주입**됨:

- SAJU_FULL: guide "요체 필수·시적 금지"(context-builder.ts:440) ↔ outputFormat "~합니다체·시적 적극 활용"(saju.ts:355-361) ↔ 마스터 무속체 — **셋이 한 프롬프트에**
- TREND: "무속 표현('~군요') 금지"(trend.ts:152)가 마스터 자신의 지정 화법을 금지
- COMPATIBILITY·관상/손금은 마스터를 아예 우회 — 별도 인격
  → AI 목소리 비결정적 + 토큰 낭비 + 브랜드 인격 분열.

**해법**: 페르소나는 하나, **화법 레지스터만 3단계**로 공식화:

| 레지스터             | 사용처                         | 어미                                  | 예                                  |
| -------------------- | ------------------------------ | ------------------------------------- | ----------------------------------- |
| **R1 격식** (문서체) | 사주 종합/신년/궁합 리포트     | ~합니다, 절제된 물상 비유 1개/단락    | "금 기운이 재물의 그릇을 이룹니다"  |
| **R2 친근** (상담체) | 데일리/트렌드/미니 리딩        | ~요/~에요, 유명인 비유                | "손흥민처럼 후반에 강한 타입이에요" |
| **R3 신비** (신당체) | 신당지기 대화, 문안, 부적 문구 | ~하오/~구려/~이오 (과하지 않게 30%만) | "오늘은 서쪽 바람이 이롭소"         |

- 구현: `lib/ai/persona.ts`에 레지스터 정의 단일화 → 마스터 프롬프트의 화법 조항 제거, `getAnalysisTypeGuide`가 레지스터 코드만 참조
- DB `ai_prompts` 마스터 템플릿에서 "무속인 화법" 조항을 R-코드 치환자로 교체

### 5.2 해석 패턴 표준: "적중 → 공감 → 처방" 3막 구조

이미 CHEONJIIN/SHAMAN_CHAT에 있는 "과거 역추산 → 현재 공감 → 미래 처방" 패턴이 **가장 강한 신뢰 장치** → 전 분석 유형으로 확장:

1. **적중(Hook)**: 과거 대운/세운 역추산 1개 — "2023년경 큰 변화가 있었을 거예요"
2. **공감(Now)**: 현재 상태 짚기 — "요즘 ~하시죠"
3. **처방(Act)**: 시기+행동 특정 — "이달 셋째 주, 서쪽 방향"

- 관상/손금에도 적용: "눈매를 보아 결정을 미루는 편이시죠(공감) → 턱 기운이 40대 후반부터 열립니다(처방)"
- 모든 결과 JSON에 `hook`/`now`/`act` 필드 표준화 → UI 카드 3장 구조로 공통 렌더링

### 5.3 관상/손금 파이프라인 개선

1. **2단계 분석**: (1단계 FLASH) 이미지 품질·부위 검출 검증 → 부적합 시 재촬영 안내 (토큰 낭비 방지) → (2단계 PRO) 본 분석. 현재는 단발 호출로 저품질 이미지도 과금됨
2. **오행 보정치 출력**: 결과 스키마에 `elementModifiers: {wood:±5,...}` 추가 → 기운 엔진(§2) 입력
3. **교차 참조**: 관상 분석 프롬프트에 사주 요약 3줄 주입(캐시된 컨텍스트에서 추출) → "사주의 금 기운이 관상의 코 복과 상응합니다" 교차 검증 화법 — CHEONJIIN 전용이던 것을 단품 분석에도

### 5.4 공통 품질 장치

- 모든 분석 JSON 출력에 `jsonMode: true` 통일 (누락된 액션 존재)
- 결과 저장 시 `analysis_history.result_json`에 `persona_register`, `schema_version` 메타 추가 — 향후 재렌더링/AB 대비

### 6.1 통화 정리 — 2통화 고정 + 이름 통일

게임 표준(유료 젬 + 무료 코인)으로 정착:

| 통화                          | 성격      | 획득                   | 사용                                   | 아이콘           |
| ----------------------------- | --------- | ---------------------- | -------------------------------------- | ---------------- |
| **복전(福錢)** (현 복채/만냥) | 유료 재화 | Toss 충전, 멤버십 지급 | 분석, 질문권, 테마 팩, 프리미엄 아이템 | 🪙 금색 엽전     |
| **복(福)** (현 복 포인트)     | 무료 재화 | 출석/미션/공유/기원    | 일반 아이템, 소액 할인                 | ✨ 홍색 복주머니 |

- **코드/UI 전면 개명**: talisman·부적·만냥·credits 혼용 제거. `bokjeon`/`bok` 2개 키워드로 통일
- 질문권은 **소모품 인벤토리**로 재분류 (통화 아님) — "질문권 20개" 아이템처럼 표기

### 6.2 상점 구조 (단일 진입점 `/protected/shop`)

게임 상점 문법 그대로:

```
[상점 탭바]  추천 | 복전 충전 | 테마 팩 | 신물(아이템) | 소모품
─ 추천 탭 ─
  ⭐ 스타터 팩 ₩4,900 (첫 구매 한정: 복전 5만 + 조선반가 팩 + 질문권 20)  ← 가치 3배 연출
  🔥 이번 주 핫딜 (주간 로테이션)
  🎁 무료: 오늘의 복 받기 (광고 없이 출석 연동)
─ 복전 충전 탭 ─
  [₩5,900 = 5만복전] [₩11,000 = 10만+보너스5천] [₩33,000 = 30만+3만] ...
  카드 1탭 → Toss 결제창 (저장 카드면 원터치)
```

**핵심 규칙**:

1. **가격 선노출**: 모든 잠긴 기능에 비용 배지 상시 표시 — 클릭 후 "부족합니다" 금지
2. **잔액 상시 표시**: 상점/분석/신당 헤더에 🪙복전 ✨복 고정
3. **부족 시 인라인 충전**: 부족분만 계산해 "**+2만 복전 충전하고 바로 구매** (₩2,400)" 1버튼 — 페이지 이동 없이 Toss 시트
4. **원터치 재충전**: 빌링키 보유 유저는 확인 다이얼로그 1번으로 충전 완료 (기존 멤버십 빌링키 재활용)
5. **구매 확인은 시트 1장**: 아이템 이미지 + 가격 + 잔액 변화 미리보기 → [구매] — 게임 UX 표준

### 6.3 마이그레이션 순서

1. UI 라벨 통일(복전/복) → 2. `/shop` 신설(기존 충전/멤버십 페이지 흡수) → 3. 인라인 충전 시트 → 4. 스타터 팩 + 테마 팩 SKU → 5. 기존 페이지 리다이렉트
