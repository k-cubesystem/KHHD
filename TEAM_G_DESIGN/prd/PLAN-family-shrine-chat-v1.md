## 1. 가족별 신당 (핵심 신기능)

**개념**: 신당을 "점사 대상"별로 — 본인 1개 + 등록 가족마다 1개. 각 신당에 그 사람 사주로 추천된 신이 좌정.

### 구조

- `shrines`에 `family_member_id UUID NULL` 추가 (NULL=본인 신당). UNIQUE(user_id, family_member_id).
- **신당 개수 = 가족 등록 한도와 자동 일치** (기존 `relationship_limit` 재사용: 무료 3명 / 플랜별 membership_tiers 값 / 관리자 10명). 별도 한도 신설 불필요 — "가족을 등록하면 그 가족의 신당을 만들 수 있다".
- 신 배정: 기존 `assignGuardian(focus_areas, 용신)`을 가족 사주로 실행 → 가족마다 수호신 자동 좌정. 신위 보유(user_shrine_deities)는 계정 단위 유지하되 **좌정(main_deity_id)은 신당별**.
- 인연(緣)·신탁·표정도 신당별(user_deity_bonds에 shrine_id 또는 family_member_id 스코프 추가).

### UI

- 신당 페이지 상단에 **대상 탭** (본인 | 가족1 | 가족2 | + 새 가족): 고민상담의 "점사 대상" 드롭다운과 동일 패턴. 오행 정령 아바타(family avatar_id 재사용)로 탭 표시.
- 가족 신당 첫 진입: 강신 의식(기존 연출)으로 그 가족의 추천 수호신 자동 좌정 — "OO님의 사주엔 木 기운이 필요해 청목 계열 신이 오셨습니다" 카피.
- 가이드바(HUD)·氣運 균형·추천 신물도 그 가족 사주 기준으로 전환.
- **고민상담 연동**: 가족 선택 대화에도 그 가족 신당의 主神 페르소나 적용(현재 본인 전용인 buildShrineContext를 대상별로 확장) → §0의 ⚠️ 해소.

### 마이그레이션 요점

1. `shrines` ALTER(family_member_id, UNIQUE 교체, RLS 갱신) — 기존 행은 family_member_id=NULL로 자연 호환.
2. `user_deity_bonds`에 스코프 컬럼(bond를 신당별로).
3. scene.ts 로드 경로에 대상 파라미터. autoSeatGuardian 가족 버전.
4. 가족 삭제 시 신당 CASCADE.

## 2. 채팅 보존 정책 — 멤버십 차등 + 확장 아이템

### 보존 정책 (제안)

| 등급     | 종료 세션 보존 | 근거                                    |
| -------- | -------------- | --------------------------------------- |
| 무료     | **30일**       | 가벼운 체험. 장기기억·요약은 영구(아래) |
| SINGLE   | 90일           |                                         |
| FAMILY   | 180일          |                                         |
| BUSINESS | 365일          |                                         |

- **삭제 대상은 "종료된 세션(ended_at NOT NULL)의 원문 메시지"만.** 활성 세션은 무기한.
- **지혜는 남긴다**: 삭제 전 세션 요약(chat_sessions.summary)과 장기기억(user_ai_memory)은 이미 별도 보존 → 원문이 지워져도 신은 "기억"함. (이미 구현된 요약/기억 시스템 덕에 자연스러움 — 카피: "오래된 문답은 연기로 흩어지나, 신은 그 뜻을 기억합니다")
- 구현: 일일 cron 1개(`/api/cron/chat-retention`) — `ended_at < now() - 보존기간` 세션의 메시지 DELETE, 세션 행은 summary만 남기고 유지.
- 과거 세션 열람 UI(세션 목록)는 보존기간 내 세션 대상으로 추가(§0 ⚠️ 해소, P2).

### 확장 아이템 — "기억의 함(記憶函)" (신당 배치형)

- 신당 상점 아이템: **기억함** (예: 3복채). **신당에 배치하면 채팅 보존기간 +90일**. 최대 2개(스택 +180일).
- 배치를 빼면 효과 소멸(다시 배치하면 복원) — "신당에 모셔둬야 효험" 세계관 정합.

## 3. 배치 아이템 = 기능 해금 시스템 (재미 확장)

`shrine_item_catalog`에 `unlock_effect JSONB` 추가 → 배치 여부로 기능 토글. 1차 라인업:

| 아이템                       | 배치 효과                                | 구현 난도                       |
| ---------------------------- | ---------------------------------------- | ------------------------------- |
| **기억함** (신규)            | 채팅 보존 +90일/개 (§2)                  | 低 — retention cron이 배치 확인 |
| **향로** (기존)              | 신탁 선톡 빈도 상한 완화 (2일1회→1일1회) | 低 — oracle 판정에 배치 체크    |
| **초롱** (기존)              | 오늘의운세에 "행운의 시간" 한 줄 추가    | 中 — daily prompt 플래그        |
| **놋방울** (기존)            | 신당 입장 시 主神이 이름 불러주는 인사   | 低 — greeting 분기              |
| **복 부적** (기존)           | 출석 보상 +10% (반올림)                  | 低 — attendance에 배치 체크     |
| **청죽 등 오행 신물** (기존) | (이미 구현) 氣運 균형 보정               | ✅ 기존                         |

- 원칙: 효과는 **소소하고 명확**(수치 1개), 서버에서 배치 여부 검증(placements 조회), 카탈로그 JSONB로 선언해 코드 분기 최소화.
- 상점/보관함 카드에 "배치 효험" 뱃지 노출 → 구매 동기 강화.

## 4. 구현 순서 (새 세션에서)

1. **[P1] 가족별 신당** — 마이그레이션 → scene 대상 파라미터 → 신당 탭 UI → 가족 자동좌정 → 고민상담 신위 페르소나 대상별 확장. (가장 큼, 세션 1~2개)
2. **[P1] 채팅 보존 cron + 멤버십 차등** — membership_tiers에 chat_retention_days 컬럼 + cron 라우트 + vercel.json 등록. (작음)
3. **[P2] 기억함 아이템 + unlock_effect 시스템** — 카탈로그 컬럼 + 아이템 1종 생성(이미지 파이프라인) + retention 연동 → 이후 향로/방울/부적 효과 순차.
4. **[P2] 과거 세션 열람 UI** (보존기간 내).
5. (연계) 멤버십별 무료신 패키지·충전↔멤버십 UI 분리(PLAN-shrine-guide-membership-v1 §1·§2)는 가족별 신당과 함께 멤버십 페이지 개편으로 묶어 진행.
