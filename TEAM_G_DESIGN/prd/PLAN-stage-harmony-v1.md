# PLAN — 「한 붓의 무대」: 배경·살림 조화 재설계 v1

작성 2026-08-09 밤 · 발단: CEO 실기기 검수 반려(스크린샷 3장) — "배경이미지와 선반·제단·간판이
어우러지지 않는다. 위에 놓이는 것과 뒤의 배경이 설계가 달라 각자 논다. 서로 설계를 합쳐서
잘 어우러지게 배경을 다시 설계하라. 테마는 그대로."

## 0. 진단 — 따로 노는 원인 3가지

| #   | 원인                    | 증상(스샷)                                                                                                               |
| --- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 1   | **그림 속 가구의 경쟁** | 중앙 뮤럴에 배경 자체 가구(책장·선반·기물)가 그려져 있고 그 앞에 제단·단상 스프라이트가 또 놓임 — "방 안에 방을 또 차림" |
| 2   | **화풍·광원 계보 분리** | 뮤럴=원화 재현(회화풍·자체 광원) vs 살림·현판=아이템 파이프라인(선명 윤곽·난색 채도·정면 위 광원) — 스티커로 읽힘        |
| 3   | **좌우 벽 밀도 공백**   | 선반장·의식각 자리 확보용 무가구 벽이 "완성된 빈 벽"이 아니라 "덜 그린 허연 벽" — 그 위 가구가 더 붕 뜸                  |

**공정 결함(재발 방지 핵심)**: 지난 회차 검수는 **뮤럴 단독**이었다. 사용자가 보는 화면은
살림·신위·현판이 얹힌 합성 화면인데, 그 화면으로 검수한 적이 없다. → 이번 회차부터
**판정 단위 = 합성판**(측정 설계 교훈 「지각 품질은 렌더 스케일에서·먼저 눈으로」의 확장).

## 1. 원칙 — 설계 통합 계약

1. **배경 = 건축과 공기만.** 벽·기둥·창(중앙만)·바닥·절제된 벽 장식(족자·문양)까지.
   **가구·기물은 전 구간(중앙 포함) 금지** — 가구는 전부 살림 레이어의 몫. 테마 정체성은
   가구가 아니라 건축·재질·빛·소품 디테일로 낸다.
2. **살림이 스타일 정본.** 생성 참조 = 테마 원화(색·세계 앵커) + **실제 살림 스프라이트
   3종(단상·제단 상판·사방탁자)**(화풍·광원 앵커). "이 가구들이 놓일 방을 같은 붓으로
   그려라"가 프롬프트의 척추. 광원은 살림 그림자와 일치(정면 위 부드러운 난색, 위→아래).
3. **자리를 아는 벽.** 표준 기하(선반장 왼벽 x 7·16·25·34 / 오른쪽 x 63.5·72.5 /
   의식각 x 88.75 / 제단 x 45~55)의 자리에 은은한 받침 — 벽 패널 리듬·바닥 톤 변화 수준.
   ⚠️ 좌표 정밀 지시는 프롬프트로 안 되므로 "일정 간격의 벽 패널/기둥 리듬"으로 유도하고,
   정밀 자리 요소가 필요하면 **결정론 렌더 레이어**(후속)로 얹는다 — AI에 좌표를 맡기지 않는다.
4. **좌우 벽 = 완성된 빈 벽.** 무창·무문 유지하되 창호 패널·재질 질감·은은한 명암 리듬으로
   "비웠지만 다 그린" 벽. 허연 미완 벽 금지.
5. **판정 = 합성판.** 뮤럴 후보 위에 실좌표·실스케일로 단상+제단+신위 1좌+가족 선반장
   3좌+의식각 현판+제물 소수를 합성한 QA판으로 육안 판정. 뮤럴 단독 판정 금지.
6. **변경 반경 최소.** 테마 16종 유지 · 기하/시드/좌표/코드 변경 0 · **뮤럴 webp 교체만**.
   구 뮤럴은 백업 보존(원복 레버). 카드용 room.webp 무접촉.

## 2. 실행 — 시범 게이트 방식 (앰비언트 v1~v5·씬 파노라마 전례 승계)

- **R1 파이프라인**: `scripts/shrine-assets/stage-theme-harmony.mjs` 신설(정본 후보).
  `stage-theme-scene.mjs`(현 정본)는 원복 레버로 존치. 참조 이미지 다중 주입(원화+살림 3종),
  C(중앙)→L→R 3샷 연속 생성·크로스페이드 조립·벽 62%/바닥 40% 슬라이스는 scene 방식 승계.
  **합성 QA판 생성기 내장**(기하 JSON 좌표로 살림·신위·현판 합성, 렌더 스케일).
- **R2 시범 1테마 = 반가** → 합성판 CEO 검수 → 반려 어휘를 프롬프트 표에 처방 후 재시안.
- **R3 GO 시 15테마 확산** → 전 장 합성판 육안 → 시드 무변경 배포(파일 교체) → 게이트
  (용량 테마당 ≤1.5MB·뮤럴 실재 테스트) → 프로덕션.
- 병행 검토(시범 결과 보고 결정): 선반장 노란 자리 매트 톤다운, 현판 명도 조정 등
  **살림 쪽 미세 보정**은 배경 재설계로 부족할 때만.

## 3. 프롬프트 규율 (반려 4연속 교훈 승계)

- 설명을 늘리지 말고 **관찰 가능한 사실**로만: "가구가 하나도 없는 방", "벽은 창호 패널이
  일정한 간격으로", "빛은 위에서 부드럽게 내려온다" 급. 메타 지시(CRITICAL 등) 금지.
- 반려 어휘는 테마별 identity 문장으로 축적(씬 파노라마 방식 그대로).
- 육안 규율: 후보마다 합성판 생성 → 사람 눈 판정. 수치 게이트는 보조.

### 추기 3 (2026-08-10 오후) — 무대 규격 v3: 밀도·화질·크롭 동시 해결

**CEO 3차 피드백**: ①"벽·바닥만 있으니 퀄리티가 안 살아 — 슬라이드 더 길어도 되니 공간 활용,
단 육안 5항목은 지켜라" ②"모바일에서 4K인데 화질이 안 좋다" ③"배경이 전부 확대돼 나온다".

**진단(실측)**: ②③은 같은 뿌리 — 뮤럴이 기준 뷰포트(≈520px)의 밴드 비율(벽 4.33:1)로
잘려 있는데 실폰 밴드는 3.0~3.3:1 → `object-cover`가 세로 맞춤 후 **가로 20~25% 크롭+확대**
(반가는 구규격 6.4:1이라 최악). 저장본 3435px는 DPR3 소요(≈3.7~4.1k px)보다 작아
크롭과 겹치면 **1.3~1.4× 업스케일**. 4K는 생성 해상도일 뿐 저장·렌더가 깎아먹고 있었다.

**규격 v3 (해법 — 재생성 1회로 ①②③ 동시 해결)**:

1. **생성 16:9 · 4K**(21:9 폐기): 세로 여유를 확보해 벽(상부 헤드룸)·바닥(전경 심도) 모두
   전 기기 밴드 비율을 덮는다. 수평선 60% 폐루프·발밑 램프·통짜 원샷은 유지.
2. **렌더 = width-fit 고정**(object-cover 폐기): 벽 이미지는 밴드 **하단 앵커**(수평선=마루선
   접지 불변), 바닥은 **상단 앵커**, 가로는 항상 월드 폭 100%(크롭 0), 세로 잉여는 밴드가
   클립. 기기별 확대·크롭 소멸, 수평선 전 기기 고정.
3. **수출 2렌디션 + srcset**: 고해상(≈5.4k px, DPR3 수퍼샘플)+표준(2048, 저사양/저DPR).
   용량 예산 테마당 ≤2.5MB로 상향(srcset이 모바일 다운로드를 표준본으로 제어 — LCP 방어).
4. **밀도 규칙(육안 5항목 준수 하에)**: 가구 0 불변. 대신 —
   · **개구부 원경**: 칸 리듬 중 일부 칸이 열려 테마의 원경이 보인다(달집=마당 너머 달집더미와
   보름달, 설빛=설경, 용궁=심해 원경…). 선반장(x7~34·63.5~72.5)·의식각(88.75) 앞 벽은
   여전히 닫힌 차분한 벽 — 개구부는 그 사이 칸으로(정밀 좌표는 프롬프트 금지, 리듬으로).
   · **상부 밀도**: 서까래·보·단청 띠·(글자 없는) 장식 — 벽 상부 1/3이 이야기한다.
   · **바닥 변주**: 문양·돗자리·재질 경계 — 민짜 널 금지.
5. **월드 폭은 320% 유지 권고**: "슬라이드 연장"은 폭당 해상도를 희석(같은 원판을 더 늘려
   깖)하므로 v3에 안 섞는다. 연장이 꼭 필요하면 별도 회차에서 «건축 구획(문틀·기둥)으로
   경계가 정당화된 경관 베이 추가 생성» 방식으로(통짜 반려 취지 위배 없음).
6. **절차**: 시범 반가(현행이 구규격 최악 + CEO 기준방) → 검수 → 전 테마 재생성(라이브
   5테마 포함 — 어차피 ①밀도 반려 대상). 구본 백업 관례 유지.
