## 0. 한 줄 결론

풍수를 **「공간을 채점하는 기능」**에서 **「집에 대해 실제로 묻는 질문에 답하는 8개의 방」**으로 다시

전부 코드가 정하고, AI는 이미 있는 두 프롬프트(`fengshui_analysis` · `trend_estate`)로 **그것을 왜

> ①첫 진단은 콕 집어서(일반론 금지) ②완충 3단 화법(나쁘다→"균형을 잃은 상태"→인정→즉시 처방)
> ③처방 없는 문제 지적 금지 ④**"이사 없이, 큰돈 들이지 않고"** ⑤희망으로 마무리

🔴 ④가 **부동산 광고 설계의 핵심 자산**이다. 우리 풍수 AI는 구조적으로 "이사 가라"고 말하지 않는다.
그래서 광고가 아래에 서도 "신령이 이사를 시켰다"가 성립하지 않는다. **이 규율을 절대 완화하지 말 것.**

## 3. 설계 원칙 — 결정론과 AI의 경계

### 3-1. 한 문장 규율

> **숫자와 날짜와 방위는 코드가 정한다. AI는 그것이 왜 그런지 말한다.**

「AI가 알아서 판정」은 세 가지 이유로 반려다: ①같은 입력에 다른 답이 나온다(재실행 비결정성)
②근거를 화면에 못 적는다 ③틀려도 잡아낼 테스트를 못 쓴다. 오방기·척전·삼합에서 이미 확립한 규율을
그대로 잇는다.

### 3-2. 3층 구조

```
[1층] 결정론 파생 — 코드가 계산 (순수 함수 · 단위테스트 대상)
        입력: 생년월일시 / 향 / 층 / 날짜 / 머리방향 / 업종
        출력: 용신 오행 · 방위 오행 · 층 오행 · 일진 간지 · 교차 등급 · 날짜별 등급
             ↓ (값을 [확정 사실] 블록으로 주입)
[2층] AI 서술 — 기존 프롬프트 2개만 사용
        fengshui_analysis  (사진 있는 테마 7종)
        trend_estate       (사진 없는 테마 1종)
        AI 가 하는 일: 사진 판독(가구·동선·채광·정돈) + 1층 값의 «왜»를 말로 푸는 것
             ↓ (태그 파싱 — 기존 파서 무변경)
[3층] 화면 — 1층 값은 코드에서 그대로 렌더, 2층 값은 태그에서 렌더
        🔴 1층 값을 AI 응답에서 되읽지 않는다. 되읽는 순간 결정론이 무너진다.
```

**주입 블록 형식** (기존 `buildFengshuiSubjectContext` 와 같은 방식으로 코드가 조립):

```
[확정 사실 — 코드가 계산한 값. 수치·날짜·방위를 바꾸지 말 것]
- 의뢰인 용신 오행: 火 / 기신 오행: 水
- 이 집의 실측 향: 북향 → 방위 오행 水
- 교차 판정: 용신(火) ↔ 향(水) = 극을 받아 눌림 / 정합도 34점 / 등급 «충»
- 층: 12층 → 끝자리 2 → 火 (용신과 같은 기운, 비화)
[서술 지시] 위 판정을 뒤집지 말고, 왜 그런지와 무엇을 하면 되는지를 [상담 화법 원칙]대로 설명하라.
```

기존 프롬프트에 이미 **"실측 향이 있으면 방위 분석의 기준으로 삼되 추측하지 말 것"** 이라는 같은
결의 문장이 들어 있다(`20260723_fengshui_context.sql`). 확장이지 신설이 아니다.

### 3-3. 새로 만드는 결정론 모듈 — **딱 하나**

`lib/domain/analysis/fengshui-cross.ts` (순수 함수, 단위테스트 대상)

| 함수(제안)                  | 입력                   | 출력                     | 근거                                                                          |
| --------------------------- | ---------------------- | ------------------------ | ----------------------------------------------------------------------------- |
| `directionElement(향)`      | 8방위 문자열           | `Element5`               | 동 木 / 동남 木 / 남 火 / 서남 土 / 서 金 / 서북 金 / 북 水 / 동북 土         |
| `floorElement(층)`          | 정수                   | `Element5`               | 하도(河圖) 생성수 — 1·6 水 / 2·7 火 / 3·8 木 / 4·9 金 / 5·10 土, 11층↑ 끝자리 |
| `industryElement(업종)`     | 업종 코드              | `Element5`               | §4-7 표 (고정 갈래)                                                           |
| `crossHouse(input)`         | 命 오행 + 宅 오행 배열 | `SamhapCoherence` 재사용 | `elementRelation` + delta 합산                                                |
| `rankMoveDates(사주, 기간)` | 사주 + 년월            | 날짜별 등급 배열         | 일진 삼합/육합/충 + 손없는날 + `calculateDailyAvoidance`                      |

🔴 **`directionElement` 의 8방위 표는 DB 프롬프트 [3단계] 의 표와 글자 그대로 같다.** 코드와
프롬프트가 다른 표를 보면 화면이 서로 다른 말을 한다 — 상수화하면서 프롬프트 표를 정본으로 삼고,
회귀 테스트로 두 표의 일치를 강제한다.

🔴 **`ELEMENT_DIRECTION` 이 지금 2곳에 중복 정의돼 있다**(`woon-calculator.ts:134`,
`yongsin-advanced.ts:89`). 새 모듈이 세 번째가 되면 안 된다 — 단일 출처로 끌어올린 뒤 역매핑을 쓴다.

🔴 **전승 갈래는 한 갈래로 고정한다.** 층수 오행은 하도수 갈래(1·6水…)로 고정. 오방기 기획서
(§1-1 "길흉 배정은 스승·지역마다 다르다")에서 확립한 규율 — 섞어 쓰면 같은 층이 화면마다 다른 말을 한다.
