# PLAN — 테마 공통 무대 v2 (16테마 완전 동등화: 두루마리부터 전부)

작성 2026-08-07 · 발단: CEO "지금까지 신당 업데이트가 다른 테마에 적용 안 돼 있다 —
슬라이드부터 전부 적용, 개선점 있으면 추가" · v1(2026-08-05)을 승계·확장한다.
v1 의 P1(간이 팻말 줄)은 출하됐고, P2/P3 는 이 문서가 대체한다.

## 0. 핵심 원칙 — 「살림과 장소」

방을 두 층으로 가른다. 이 규칙 하나가 확산 비용의 대부분을 없앤다.

- **신당 살림(고정, 테마 무관)** — 단상·제단 상판·가족 선반장(사방탁자)·의식각 현판·
  신위·신수·신물. 어느 장소로 이사해도 살림은 그대로 따라간다. → **스프라이트 공용,
  코드 공용, 좌표 공용.** 새로 그릴 것이 없다.
- **장소(테마)** — 벽·바닥(뮤럴 2장)·조명색·(후속) 시그니처 구조물. 테마당 이것만 만든다.

즉 확산의 실체는 「테마당 벽·바닥 2장 + 시드 1건」이고, 나머지(두루마리 카메라·PC 조작
3종·가족 선반장·의식각·자유 배치·신수 배회·진열 스냅)는 **전부 자동으로 켜진다** —
이미 stage jsonb 유무·worldActive 로 분기하도록 만들어 놨기 때문이다.

## 2. 표준 와이드 무대 계약 (Standard Wide Stage)

반가에서 검증된 기하를 **전 테마 공통 상수**로 못박는다. 좌표를 테마마다 다시 정하지
않는다 — 정하는 순간 선반장·의식각·앵커·테스트가 테마 수만큼 갈라진다.

```
world.width = 320 (뷰포트 3.2배) · 구역 1개(대청 0~320)
구조물: platform(단상) x50 y51 w44 · altar-top(제단) x50 y58 w58
제단 앵커: x 45/50/55 · y 53.5 (라이브 정정값 — 34/66 회귀 금지)
가족 선반장: 왼벽 4좌(x 7·16·25·34) + 오른쪽 2좌(x 63.5·72.5)
의식각: x 88.75 (구 사랑방 자리)
마루선 y 62 · 신수 배회 y 61 · 팻말/현판·진열 기하 전부 공용 상수 승계
```

- 단상·제단 상판 스프라이트는 **반가 것을 전 테마 공용**으로 쓴다(살림 원칙).
  옻칠 제단은 "신당의 가구"라 장소가 숲이든 대장간이든 세계관이 성립한다.
- 시드는 마이그레이션 스크립트가 **템플릿 1벌**에서 16건을 찍는다(코드로 좌표 복제 금지 —
  banga-wide-seed.test 를 「전 테마 공통 계약」으로 확장해 어긋남을 잡는다).

## 3. 단계 계획

### P2-a. 파이프라인 일반화 (코드, 반나절)

`stage-banga-room.mjs` → `stage-theme-room.mjs` 일반화.

- 테마별 프롬프트 표: **DB 의 story·element_affinity 를 프롬프트 씨앗**으로 쓴다
  (16테마 로어가 이미 있다 — 장소 묘사를 다시 쓰지 않는다). STYLE/LIGHT 문구는
  반가 원문 복제(같은 붓·같은 빛 규율).
- **무창·무문 규칙을 프롬프트에 명문화**(반가에서 이미 검증된 문구 재사용) — 벽 전체가
  선반장 자리라는 전제가 전 테마에 동일하다.
- 이음새·주기 밝기물결 게이트(seam/ripple 수치)와 뮤럴 조립(×4 미러 퀼트)은 반가
  파이프라인 그대로 — 이미 세로줄 사고를 막아 본 게이트다.
- 팔레트 앵커: 각 테마의 기존 room.webp 를 ref 로 — 카드·기존 방과 같은 색세계 유지.
- 조명색(stage.light): element_affinity → 오행색, 무속성은 금색.

### P2-b. 시안 1테마 — 새벽 종각(jonggak) 풀코스 (게이트: CEO 육안)

종각 벽·바닥 생성 → 뮤럴 조립 → 시드 적용(종각 1건) → **프로덕션에서 CEO 육안**.
선반장·의식각·카메라가 함께 켜진 완성형을 보고 GO/반려. 반려 어휘가 생기면
프롬프트 표에 반영 후 재시안(앰비언트 v1~v5 반려 전례의 교훈 — 한 테마로 배우고 확산).

### P2-c. 14테마 일괄 (생성 ~30장 + 재시도 여유, 육안 일괄)

- 생성·조립·게이트 통과 → **육안은 렌더 스케일에서**(원본 확대 금지 — 측정 설계 교훈).
- 시드 마이그레이션 1건으로 15테마 stage 일괄 주입(배포 순서: 코드 먼저 → 시드).
- FAMILY_SHELF_THEMES → 16 code 전부. RitualHall 게이트 → worldActive 일반화.
  GenericPlaqueBand 는 은퇴(코드는 원복 레버로 보존).
- 계약: banga-wide-seed.test → theme-wide-seed.test 로 확장(표준 기하 × 16 대조),
  뮤럴 파일 실재 테스트, 용량 상한(테마당 뮤럴 2장 합 ≤ 1.5MB) 게이트.

### P2-d. 마감

체크리스트(실기기 검수 절) 갱신 · HANDOFF/메모리 갱신 · 프로덕션 배포 · 구 room.webp 는
카드 프리뷰용으로 존치(삭제 금지 — 상점 카드가 쓴다).

## 5. 비용·리스크

- **이미지 생성**: 벽·바닥 2장 × 15테마 = 30장(+재시도 여유 ≈ 40회 호출). 단가는 기존
  아이콘·테마 파이프라인과 동일 계정. 단상·제단·살림 재생성 0장(공용 원칙).
- **시간**: P2-a 반나절 · P2-b 시안+검수 1회전 · P2-c 생성은 배치로 수십 분 + 육안 일괄.
  세션 1~2회 규모.
- **리스크 1 — 화풍 반려**: 앰비언트 v1~v5 전례. → 시안 1테마 게이트로 흡수.
- **리스크 2 — 이행기 혼재**: 일부만 wide 인 기간엔 테마 전환 시 조작감이 오간다.
  → 시드를 일괄 1건으로 적용해 이행기를 0에 수렴시킨다(시안 기간만 종각 단독 wide).
- **리스크 3 — 저장 좌표 호환**: 배치 좌표는 이미 [0,100] 공통이라 room.webp ↔ wide 전환에
  데이터 이동이 없다(자유 배치 덕에 존 재클램프도 없다). 확인 테스트만 추가.
