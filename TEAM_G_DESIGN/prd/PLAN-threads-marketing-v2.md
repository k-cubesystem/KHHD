# PLAN — 스레드 마케팅 v2 (재기획 · 비판적 재검토)

작성 2026-08-19 · 발주: CEO "다시 기획 — 분석·개선안·필요 없는 부분·새로 기획한 부분"
대상: `PLAN-threads-event-automation-v1.md`(이벤트 시스템, 코드 완성) + `PLAN-threads-content-engine-v1.md`(콘텐츠, 기획만)
방법: 두 문서를 **0 팔로워 계정이 실제로 굴러가나**의 눈으로 다시 읽고, 코드에 있는 것/없는 것을 실측해 대조했다.

---

## 0. 한 줄 결론

v1은 **「시스템이 하는 일」은 잘 짰고 「사람이 봐주는 이유」는 약했다.**
이벤트(추첨)를 엔진으로, 콘텐츠를 «봇처럼 안 보이려는 장식»으로 놓은 순서가 거꾸로다.
v2는 **이야기가 엔진, 이벤트는 «독자가 주인공이 되는 장치»**로 뒤집는다. 코드는 대부분 그대로 쓰고 **프롬프트·문구·배선 수준의 작은 변경 + 공개 페이지 1장**만 더한다.

## 1. 진단 — v1의 약점 5가지

| #   | 약점                                                                                 | 왜 치명적인가                                                                                                                                                                          |
| --- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **발견(discovery) 전략이 없다.** "글을 올리면 본다"를 전제로 짰다                    | 팔로워 0 계정의 이벤트 글은 노출 0이다. 스레드의 발견 = **답글(대화)이 랭킹 신호 + 토픽 태그 + 남의 글에 단 답글**. 시스템은 이 셋 중 하나도 안 다룬다(API가 남의 글을 못 읽으니 당연) |
| 2   | **퍼널 입구가 너무 무겁다.** 첫 클릭에서 생년월일시·성별·아이디·사연·동의를 요구한다 | 신뢰 0인 방문자에게 개인정보 폼은 이탈 지점이다. 참여 질문 「당신의 일간은?」을 던져놓고 **일간을 알아볼 곳이 없다**                                                                   |
| 3   | **보상이 약하다.** «N명 중 5명 추첨 → 간이 풀이»                                     | 복권은 동기가 약하고, 결과물(일반 풀이 카드)은 **공유할 이유가 없다**. 바이럴 루프가 없다                                                                                              |
| 4   | **콘텐츠 톤이 플랫폼과 어긋날 수 있다.** 장부체(문어·3인칭)만으로 갔다               | 한국 스레드는 20~30대·구어·일기체다. 첫 줄에서 스크롤될 위험. 검증 없이 14편을 만들면 통째로 버린다                                                                                    |
| 5   | **KPI가 단계를 무시한다.** 가입·D7·결제를 1주차부터 본다                             | 팔로워 100 전엔 가입이 0에 가깝다. 2주차에 «안 된다»고 접는 사고를 막으려면 **단계 게이트**가 있어야 한다                                                                              |

부차: 하루 2편 × 7 = 14편을 «14개 콘텐츠»로 읽으면 제작이 2배다. **1이야기 = 2박자(아침 훅·밤 결말)**로 못 박는다.

## 2. 유지 — v1에서 맞는 것 (손대지 않는다)

- 응모·개인정보는 **사이트 폼**(DM 없음·댓글로 생년월일 금지) · 「좋아요하면 추첨」 금지 · 답글은 **사람 1클릭 승인**
- **픽션 프레임(복채 장부)** — 후기 형식의 표시광고법 이중 위반 회피. 결말은 행동으로, 「그 뒤는 적혀 있지 않다」
- **첫 결제 목표 = 싱글 멤버십 9,900**(충전 10만냥 29,900의 1/3) · 가입 보너스 50만냥(사주 25회분)을 숫자로 노출
- 신청 완료 화면의 가입 CTA(낙첨 90%가 지나는 최대 지점)
- 시스템: 8테이블·크론 4종·결정론 추첨·주간 보고서·킬스위치 — **전부 그대로 쓴다**

## 5. 신규 — v1에 없던 것

### 5-A. 비로그인 「3초 일간」 페이지 — **진짜 퍼널 입구** 🔴 최우선

모든 이야기 글의 CTA 「당신의 일간은?」이 갈 곳. 생년월일(시 선택) → **일간 한 글자 + 세 줄** + 「정식 풀이는 가입 후 복채 50만냥으로」.

- 이벤트 폼(개인정보 7항목)보다 **압도적으로 가볍다** → 클릭→행동 전환이 다르다
- `calculateManse()` 순수함수라 **페이지 1장**. 저장 없음(개인정보 안 남김) · 로그인 없음 · UTM 유지
- 결과에 「내 일간으로 쓰인 장부 보기」(해당 일간 장부 링크) → 이야기로 되돌아가는 고리
- 결과 카드 OG(1080²) → 「내 일간은 경금」 공유 → **결과 카드가 광고**(v1이 바랐던 걸 여기서 이룬다)

### 5-B. 보상 재정의 — 「당첨 = 장부에 등재」

| v1                                       | v2                                                                                         |
| ---------------------------------------- | ------------------------------------------------------------------------------------------ |
| 추첨 5명 → 간이 풀이 3~4문단 → 결과 카드 | 매주 **사연 N편 선정 → 본인 실명식으로 「복채 장부 제N장」 집필 → @태그 발표**             |
| 결과물 = 일반 풀이(공유 이유 없음)       | 결과물 = **그 사람 이야기**(본인이 리포스트한다 — 바이럴 루프) = 그대로 **다음 날 콘텐츠** |
| 동기 = 복권                              | 동기 = **주인공**                                                                          |

법무: 실제 독자 사연이므로 라벨을 **「독자 장부 — 사연 @x · 각색」**으로 명시, `consent_public` 없는 사연은 등재 않음, 결말은 행동·여운(결과 약속 금지). 픽션 장부(제N장)와 독자 장부를 라벨로 구분한다.

### 5-C. 수동 발견 루틴 — 시스템 밖 하루 10분 🔴

API는 남의 글을 못 읽는다. 그래서 v1은 이걸 통째로 빠뜨렸다. **0→100 팔로워 구간에서 가장 효과 큰 행동이 수동이다.**

- 사주·운세·타로 니치의 큰 계정 글에 **해수 목소리로 실질적 답글** 5~10개/일(앱에서, 홍보 문구 없이 내용으로)
- 매 글 **토픽 태그**(사주·운세·궁합) — 팔로워 없이 노출되는 유일한 공식 경로. API 지원 여부는 **확인 필요**, 안 되면 앱에서 수동
- 투표(「당신 일간은 木·火·土·金·水?」) — API 가능 여부 확인 필요, 안 되면 하루 1건 수동

### 5-D. 시드 오디언스

기존 회원(웹푸시·공지)에게 「스레드 열었어요 — 당신 사연이 장부가 됩니다」 1회. 첫 글에 답글 10개가 붙는 것과 0개는 알고리즘이 다르게 본다. 카카오 채널이 있으면 동시에.

### 5-E. 단계 게이트 KPI — 가입을 너무 일찍 보지 않는다

| 단계 | 팔로워  | 보는 숫자 하나      | 통과선   | 안 되면                                  |
| ---- | ------- | ------------------- | -------- | ---------------------------------------- |
| 0    | 0~100   | **글당 답글 수**    | 평균 ≥ 5 | 톤 A/B 교체·주제 교체(2주 단위)          |
| 1    | 100~500 | **사연 접수 / 주**  | ≥ 10     | 등재 보상 노출 강화·일간 페이지 CTA 점검 |
| 2    | 500+    | **가입 / 주**       | ≥ 20     | 폼·완료 화면·일간 페이지 전환 점검       |
| 3    | 1,000+  | 30일 내 멤버십 전환 | ≥ 3%     | 소진 유도(인연 등록)·멤버십 안내 시점    |

## 6. 새 운영 모델

**편성(KST)** — 1이야기 = 2박자. 주 7이야기.

| 시각  | 글                                                                 | 발행 방식                       |
| ----- | ------------------------------------------------------------------ | ------------------------------- |
| 08:00 | 훅 한 줄(구어) + 장부 1~2막 + 명식 카드 + 「당신의 일간은? → 3초」 | 예약 발행(자동)                 |
| 21:00 | 3~4막 진단·반전·선택 + (장 마무리) 「그 뒤는…」                    | **아침 글의 답글로** 예약(자동) |

주간: 월 라운드 오픈(이야기 글 끝 한 줄) · 수·토 21시는 웹툰 4컷(캐러셀) · 토 08시 독자 장부 발표(@태그) · 일 21시 다음 주 예고.
**영상 없음**(팔로워 100 게이트 전).

**사람 시간**: 일요일 90분(이야기 7편 초안 검토·카드) + 매일 15분(답글 승인 5 + 수동 발견 답글 10).

**첫 2주**: 이벤트 라운드 **열지 않는다**. 이야기 7편/주 + 수동 발견 + 일간 페이지만. 팔로워·답글이 생긴 3주차에 첫 라운드(「당신 사연을 장부에」)를 연다. 빈 계정의 이벤트 글은 스팸으로 읽힌다 — v1 §5.5를 각주가 아니라 **규칙**으로 올린다.
